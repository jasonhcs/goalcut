## 一、项目简介

**GoalCut** 是一款篮球进球集锦智能剪辑工具。给定一段篮球比赛/打球视频，GoalCut 能够自动识别所有进球瞬间，裁剪进球前后的精彩片段，拼接生成一段进球集锦视频。

一句话概括：**输入一段篮球视频，输出一段进球集锦。**

## 二、产品定位

### 2.1 核心定位

> **野球场 / 业余比赛自动集锦生成工具**

GoalCut 首要服务的场景是：

- **野球场**（街头篮球、社区球场、公园球场、高校球场等）
- **业余比赛**（球友联赛、公司联赛、社区杯赛、校园比赛等）

这些场景的共同特征是：

| 特征 | 说明 |
|------|------|
| 无记分牌 | 没有电子记分牌，无法通过 OCR 检测分数变化 |
| 无解说员 | 没有专业解说，无法利用解说激动度作为信号 |
| 单机位 | 通常只有一个手机/相机固定视角拍摄，无多机位切换 |
| 无回放 | 没有慢动作回放、镜头切换等转播特征 |
| 画质参差 | 手机拍摄，分辨率从 720p 到 4K 不等，可能竖版拍摄 |
| 视角多变 | 场边、看台、底线等各种非标准视角 |

### 2.2 为什么选择这个定位

**市场空白**：通过竞品分析（详见 `competitive-analysis.md`），现有产品集中在两个极端：

```
个人训练                                              职业赛事
◄────────────────────────────────────────────────────────►
HomeCourt                                           WSC Sports
LikeSports        ★ GoalCut 瞄准的空白地带           Pixellot
篮Buff                                              Hudl/Instat
Hoop Tracker     （野球场/业余比赛自动集锦）
```

- **个人训练类**（HomeCourt、LikeSports）：需要特定摆放手机、固定视角、面向单人或 1v1 训练，不适用于多人比赛
- **职业赛事类**（WSC Sports、Pixellot、Hudl）：依赖多机位转播画面、记分牌、高清画质等条件，不适用于业余场景

**而野球场/业余比赛这个中间地带，目前没有成熟的自动集锦工具。**

### 2.3 目标用户

| 用户画像 | 典型场景 | 核心需求 |
|---------|---------|---------|
| **野球爱好者** | 周末约球打半场/全场，手机架在场边录像 | 打完球快速生成进球集锦，发朋友圈/球友群 |
| **球友群群主** | 组织球友联赛、定期约球 | 每场比赛自动出集锦，活跃社群氛围 |
| **校园篮球社团** | 校园联赛、院系杯赛、日常训练赛 | 低成本生成比赛集锦，宣传社团活动 |
| **篮球自媒体博主** | 拍摄街头篮球、野球场素材 | 快速从长视频中提取进球精华，提升内容创作效率 |
| **业余球队教练** | 球队训练赛、内部对抗赛 | 回看进球片段，简单复盘 |

### 2.4 核心使用流程

```
用户拍摄打球视频（手机/相机）
        │
        ▼
  将视频文件交给 GoalCut
  （Phase 1: 命令行输入；Phase 2+: Web 上传）
        │
        ▼
  GoalCut 自动分析视频
  ├─ AI 检测所有进球瞬间
  ├─ 裁剪每个进球前后各 N 秒
  └─ 拼接成一段完整集锦视频
        │
        ▼
  用户获得进球集锦视频
  ├─ 分享到社交平台（微信/抖音/朋友圈）
  ├─ 发到球友群
  └─ 个人收藏回看
```

## 三、项目起源与动机

### 3.1 痛点描述

每次打完球，球友们都想回看自己的进球瞬间。但现实是：

1. **原始视频太长**：一场球打 1～2 小时，没人愿意从头看完
2. **手动剪辑太累**：用剪映/PR 手动找进球、裁剪、拼接，一段视频剪 30 分钟以上
3. **现有工具不适配**：HomeCourt/LikeSports 面向训练（单人投篮），无法处理多人对抗的比赛场景
4. **专业方案门槛高**：WSC Sports/Pixellot 面向职业赛事，需要专用硬件或多机位转播条件

**GoalCut 要解决的问题**：让普通球友也能零门槛地从打球视频中自动获得进球集锦。

### 3.2 产品愿景

- **短期**：一个好用的命令行工具 —— 输入视频，输出集锦
- **中期**：一个 Web 应用 —— 上传视频，在线预览/下载集锦
- **长期**：一个篮球内容平台 —— 自动集锦 + 数据统计 + 社交分享

## 四、技术路线概要

### 4.1 核心技术挑战

野球场/业余比赛场景下，进球检测面临的特殊挑战：

| 挑战 | 说明 | 应对策略 |
|------|------|---------|
| 无记分牌 | 不能依赖 OCR 检测分数变化 | 以视觉轨迹检测为主力（权重 0.70） |
| 画面遮挡 | 多人对抗，球员之间相互遮挡 | 多帧轨迹分析 + 篮网形变辅助 |
| 非标准视角 | 手机拍摄角度不固定 | 自适应 ROI 检测，适配多种视角 |
| 竖版视频 | 手机竖拍常见 | 兼容横版/竖版，动态调整检测区域 |
| 画质不稳定 | 光线、抖动、分辨率参差不齐 | 多策略检测（轨迹 + 帧差分 + 活跃度）互为回退 |

### 4.2 进球检测策略（野球场模式）

```
┌─────────────────────────────────────────────────────┐
│              野球场模式 进球检测信号                      │
├─────────────────────────────────────────────────────┤
│                                                     │
│   ┌─────────────────────┐                           │
│   │  视觉轨迹检测 (0.70)  │  ← 主力信号               │
│   │  YOLO 检测篮球位置    │                           │
│   │  轨迹分析判断进球      │                           │
│   └─────────────────────┘                           │
│                                                     │
│   ┌─────────────────────┐                           │
│   │  篮网形变检测 (0.20)  │  ← 关键辅助信号            │
│   │  光流法/帧差分检测     │                           │
│   │  篮网晃动 = 进球      │                           │
│   └─────────────────────┘                           │
│                                                     │
│   ┌─────────────────────┐                           │
│   │  音频分析 (0.10)      │  ← 补充信号               │
│   │  入网声 / 叫好声      │                           │
│   └─────────────────────┘                           │
│                                                     │
│   融合置信度 → 阈值过滤 → 事件去重 → 进球事件列表       │
└─────────────────────────────────────────────────────┘
```

### 4.3 技术栈

| 层 | 技术选型 |
|----|---------|
| 后端核心 | Go（高并发、高性能视频处理流水线） |
| AI 引擎 | Python（YOLOv8 目标检测 + 轨迹分析 + 多模态融合） |
| 视频处理 | FFmpeg（解码/编码/裁剪/拼接） |
| 前端（Phase 2+） | React + TypeScript + Ant Design |

详细技术栈参见 `feasibility-analysis.md` 第四节。

## 五、项目当前状态

### 5.1 阶段进展

| 阶段 | 说明 | 状态 |
|------|------|------|
| **Phase 0** | 基础设施搭建（Go CLI + Python AI 脚本） | ✅ 已完成 |
| **Phase 1** | MVP 核心链路（视觉检测 → 集锦生成，纯命令行） | ✅ 已完成 |
| **Phase 2** | 完整 Web 应用 + 多模态检测增强 | ⬜ 待开始 |
| **Phase 3** | 体验完善 + 外部组件引入 | ⬜ 待开始 |
| **Phase 4** | 生产就绪（容器化、监控、安全） | ⬜ 待开始 |

### 5.2 Phase 1 已实现能力

```bash
# 单文件处理
go run cmd/goalcut/main.go -input basketball.mp4

# 文件夹批量处理
go run cmd/goalcut/main.go -input ./videos/ -output ./highlights/
```

- 输入：本地篮球视频文件（MP4）
- 处理：YOLOv8 预训练模型检测篮球 → 启发式轨迹分析判断进球 → FFmpeg 裁剪拼接
- 输出：进球前后各 3 秒的拼接集锦视频（`原文件名_goalcut.mp4`）
- 测试：2 段测试视频验证通过（横版 + 竖版）
- 依赖：仅需 Go 1.21+ / Python 3.10+ / FFmpeg，零外部组件

### 5.3 已知局限（待后续迭代改进）

| 局限 | 说明 | 改进计划 |
|------|------|---------|
| 仅视觉单模态 | 当前只有 YOLO 视觉检测，无音频/OCR | Phase 2 增加多模态 |
| 预训练模型 | 使用 COCO 通用模型，非篮球专用 | 后续收集数据微调 |
| 固定 ROI | 篮筐区域基于画面比例固定 | 后续增加动态检测 |
| 无追踪器 | 简化的帧间位置比较替代 ByteTrack | 后续集成正式追踪器 |
| 仅命令行 | 无 Web 界面 | Phase 2 构建 Web 应用 |
