## 一、概述

### 1.1 核心问题

篮球进球检测的本质是一个**视频事件识别问题**：在连续的视频流中，判断某一时刻篮球是否穿越篮筐进入篮网，并精确定位该事件的时间戳。

这一问题的核心难点在于：

- **信号稀疏**：一场 90 分钟比赛中进球事件只有 40~80 次，仅占总帧数的极小比例
- **场景差异大**：正式比赛有记分牌、多机位、解说员；野球场仅有单机位固定视角，无任何辅助信息
- **视觉干扰多**：球员遮挡、球体运动模糊、镜头抖动、光线变化等
- **单一信号不可靠**：任何单一检测维度都存在误报或漏报

GoalCut 采用**多模态信号融合 + 场景自适应权重**的策略，综合多维度信号进行进球判断。

### 1.2 市场竞品对比

在研究 GoalCut 算法之前，先梳理市场上主流产品的进球检测思路：

| 产品 | 核心方法 | 准确率 | 适用场景 | 局限 |
|------|---------|--------|---------|------|
| **Second Spectrum**（NBA 官方） | 多摄像头 3D 光学追踪，重建球的三维轨迹穿越篮筐平面 | ~100% | 职业赛场（需固定安装 6+ 摄像头） | 硬件成本极高，不可移植 |
| **WSC Sports** | 记分牌 OCR 为主信号，叠加解说 NLP + 欢呼声 + 镜头切换 | >99% | 正式比赛直播信号 | 强依赖记分牌和直播数据流 |
| **Pixellot** | 全景拼接摄像头 + 运动跟踪 AI，检测球在篮筐区域的轨迹 | ~95% | 需固定安装全景摄像头 | 依赖专有硬件 |
| **HomeCourt**（面向个人） | 单摄像头视觉追踪，检测球穿越篮筐 ROI 且方向向下 | 85~95% | 单机位固定视角，环境要求严格 | 遮挡/光线差时准确率下降 |
| **学术/开源方案** | YOLO 检测 + 轨迹追踪 + 几何判断，帧差分辅助 | ~95% | 通用场景 | 遮挡/对抗时误判率高 |

**核心观察**：

1. 所有成熟产品都采用多信号融合策略，没有任何单一方法是完美的
2. 记分牌 OCR 是正式比赛中准确率最高的信号（接近 100%），但对野球场完全无效
3. **野球场单机位场景目前市面上没有成熟的商业产品**，是 GoalCut 的核心差异化机会
4. 竞品几乎不使用篮网形变检测和入网声检测，这是 GoalCut 可以利用的独特信号

## 二、场景模式与检测策略

### 2.1 两种场景的信号差异

GoalCut 需要同时适配两种截然不同的场景：

| 信号维度 | 正式比赛 | 野球场 | 备注 |
|---------|---------|--------|------|
| 记分牌 | ✅ 有（画面固定位置） | ❌ 无 | 野球场核心缺失 |
| 解说员 | ✅ 有 | ❌ 无 | — |
| 多机位/回放 | ✅ 有（进球后常有回放） | ❌ 无 | — |
| 观众欢呼声 | ✅ 有（大量观众） | △ 弱（少数球友） | 信号强度差异大 |
| 篮球入网声 | △ 有（但被环境声掩盖） | ✅ 较清晰（安静场地） | — |
| 球友叫好/击掌 | ❌ 无 | ✅ 有 | — |
| 篮球/篮筐视觉 | ✅ 有（固定机位或跟拍） | ✅ 有（固定单机位） | 共有信号 |
| 篮网形变 | ✅ 有 | ✅ 有 | 共有信号，野球场更明显 |

### 2.2 场景自动识别

系统在处理视频开始时，自动分析视频前 10 秒，判断场景类型：

```python
def detect_scene_mode(video_path: str) -> str:
    """
    分析视频前 10 秒，判断场景类型。
    返回: 'official'（正式比赛）或 'pickup'（野球场）
    """
    has_scoreboard = detect_scoreboard_region(video_path, duration=10)
    has_multi_camera = detect_camera_switches(video_path, duration=10)

    if has_scoreboard or has_multi_camera:
        return 'official'
    return 'pickup'
```

用户也可以手动指定场景模式，覆盖自动识别结果。

### 2.3 动态权重分配

根据场景模式，各检测维度的权重动态调整：

| 检测维度 | 正式比赛权重 | 野球场权重 | 调整原因 |
|---------|------------|-----------|---------|
| 记分牌 OCR | **0.40** | 0.00（禁用） | 野球场无记分牌 |
| 视觉轨迹检测 | 0.30 | **0.70** | 野球场主力检测手段 |
| 篮网形变检测 | 0.00 | **0.20** | 进球后篮网晃动，野球场更清晰 |
| 音频分析 | 0.15 | 0.10 | 野球场仅检测入网声/叫好声 |
| 场景变化检测 | 0.15 | 0.00（禁用） | 野球场无回放/慢动作 |

## 三、检测流水线总览

```
原始视频输入
    │
    ├─── [阶段 0] 场景模式识别
    │    └─ 分析前 10s，自动判定 official / pickup
    │
    ├─── [阶段 1] 预处理
    │    ├─ FFmpeg 视频解码
    │    ├─ 关键帧提取（2~5 fps 自适应采样）
    │    └─ 音频轨道分离
    │
    ├─── [阶段 2] 并行多模态检测（根据场景模式启用/禁用各 Pipeline）
    │    │
    │    ├─ Pipeline A：视觉轨迹检测（所有模式）
    │    │   ├─ YOLO 检测篮球 + 篮筐 + 球员
    │    │   ├─ ByteTrack 追踪篮球运动轨迹
    │    │   └─ 几何判断：球穿越篮筐平面且方向向下 → 进球候选
    │    │
    │    ├─ Pipeline B：篮网形变检测（野球场模式增强）
    │    │   ├─ 定位篮网 ROI 区域
    │    │   ├─ 光流法 / 帧差分计算该区域运动量
    │    │   └─ 运动量超过阈值 → 篮网晃动候选
    │    │
    │    ├─ Pipeline C：记分牌 OCR（仅正式比赛模式）
    │    │   ├─ 自动定位记分牌区域
    │    │   ├─ PaddleOCR 识别比分数字
    │    │   └─ 分数跳变 → 得分事件
    │    │
    │    ├─ Pipeline D：音频分析（所有模式，策略不同）
    │    │   ├─ 正式比赛：欢呼声音量峰值 + 解说激动度
    │    │   └─ 野球场：入网声（Swish）+ 球友叫好/击掌声
    │    │
    │    └─ Pipeline E：场景变化检测（仅正式比赛模式）
    │        ├─ 镜头切换检测（硬切/渐变）
    │        └─ 慢动作回放检测
    │
    ├─── [阶段 3] 多模态融合
    │    ├─ 时间轴对齐（各维度结果对齐到统一时间轴）
    │    ├─ 加权融合置信度（动态权重）
    │    ├─ 阈值过滤（默认阈值 0.5）
    │    └─ 事件去重与合并（同一进球的多次检测合并）
    │
    └─── [阶段 4] 输出
         └─ 进球事件列表 [{timestamp, score_type, confidence, detections}]
```

## 四、各检测维度详解

### 4.1 视觉轨迹检测（Pipeline A）

视觉轨迹检测是所有场景的核心检测手段，在野球场模式下权重高达 0.70。

#### 4.1.1 目标检测

使用 **YOLOv8** 对每帧（采样帧）进行目标检测，检测以下类别：

| 检测目标 | 说明 | 用途 |
|---------|------|------|
| `basketball` | 篮球 | 轨迹追踪 |
| `hoop` | 篮筐/篮圈 | 确定进球区域 |
| `net` | 篮网 | 形变检测 ROI |
| `player` | 球员 | 遮挡处理，辅助判断投篮类型 |

#### 4.1.2 目标追踪

使用 **ByteTrack** 对篮球进行跨帧追踪，输出带 ID 的球体轨迹序列：

```
轨迹点序列: [(t₁, x₁, y₁, conf₁), (t₂, x₂, y₂, conf₂), ...]
```

追踪策略：
- 置信度低于 0.3 的检测框不参与追踪初始化，但可用于补全轨迹（ByteTrack 二阶段匹配）
- 追踪丢失超过 1 秒则终止该轨迹，等待重新初始化

#### 4.1.3 进球几何判定

这是视觉检测的核心逻辑，参考竞品（HomeCourt、学术方案）的最佳实践，采用**严格几何判断**而非简单区域包含：

```python
def judge_goal_by_trajectory(trajectory: List[Point], hoop: Rect) -> GoalResult:
    """
    通过球体轨迹判断是否进球。

    判定条件（需同时满足）：
    1. 球体轨迹在篮筐区域上方出现
    2. 球体运动方向向下（Y 轴坐标递增）
    3. 球体中心穿越篮筐内圈平面（水平线 y = hoop.center_y）
    4. 穿越点的 X 坐标在篮筐内圈范围内（hoop.left ~ hoop.right）
    5. 连续至少 3 帧满足以上条件（防误判）
    """
    crossing_frames = []

    for i in range(1, len(trajectory)):
        prev, curr = trajectory[i-1], trajectory[i]

        # 条件2：方向向下
        if curr.y <= prev.y:
            continue

        hoop_y = hoop.center_y
        # 条件3：穿越篮筐水平线
        if not (prev.y < hoop_y <= curr.y):
            continue

        # 线性插值计算穿越时的 X 坐标
        ratio = (hoop_y - prev.y) / (curr.y - prev.y)
        cross_x = prev.x + ratio * (curr.x - prev.x)

        # 条件4：穿越点在篮筐内圈范围内（加容差 ±10%）
        margin = hoop.width * 0.1
        if hoop.left - margin <= cross_x <= hoop.right + margin:
            crossing_frames.append(i)

    # 条件5：连续帧确认
    if len(crossing_frames) >= 2:
        goal_timestamp = trajectory[crossing_frames[0]].time
        confidence = min(1.0, len(crossing_frames) / 3.0)
        return GoalResult(detected=True, timestamp=goal_timestamp, confidence=confidence)

    return GoalResult(detected=False)
```

**关键设计决策**：

> 竞品的主要误判来源之一是"球在篮筐附近但未进"的场景（如擦框弹出、篮下对抗）。采用**方向向下 + 穿越内圈平面**的严格几何判断，可以有效排除这类误判。

#### 4.1.4 冷静期机制

进球确认后设置 **2 秒冷静期**，期间忽略新的进球候选，防止同一进球被重复计数（球弹网多次触框）。

### 4.2 篮网形变检测（Pipeline B）

篮网形变检测是 GoalCut 的**差异化特色信号**，市面竞品几乎不使用，在野球场模式下权重为 0.20。

**物理原理**：篮球进网后，篮网受到冲击会产生明显的形变和晃动，这是进球的可靠物理信号，即使在球体检测置信度低的情况下也能生效。

#### 4.2.1 篮网 ROI 定位

```python
def get_net_roi(hoop: Rect, frame_height: int) -> Rect:
    """
    根据篮筐位置推算篮网 ROI 区域。
    篮网位于篮筐下方，高度约为篮筐宽度的 1.5 倍。
    """
    return Rect(
        left=hoop.left - hoop.width * 0.1,
        top=hoop.center_y,
        right=hoop.right + hoop.width * 0.1,
        bottom=min(hoop.bottom + hoop.width * 1.5, frame_height)
    )
```

#### 4.2.2 形变量计算

使用**光流法（Lucas-Kanade）**计算篮网 ROI 区域内的像素运动量：

```python
def calc_net_deformation(frame_prev: np.ndarray, frame_curr: np.ndarray,
                          net_roi: Rect) -> float:
    """
    计算篮网区域的形变量（归一化到 0~1）。
    返回值越大，篮网晃动越明显。
    """
    roi_prev = crop_roi(frame_prev, net_roi)
    roi_curr = crop_roi(frame_curr, net_roi)

    # 转灰度
    gray_prev = cv2.cvtColor(roi_prev, cv2.COLOR_BGR2GRAY)
    gray_curr = cv2.cvtColor(roi_curr, cv2.COLOR_BGR2GRAY)

    # 计算光流
    flow = cv2.calcOpticalFlowFarneback(
        gray_prev, gray_curr, None,
        pyr_scale=0.5, levels=3, winsize=15,
        iterations=3, poly_n=5, poly_sigma=1.2, flags=0
    )

    # 计算平均运动幅度
    magnitude = np.sqrt(flow[..., 0]**2 + flow[..., 1]**2)
    avg_magnitude = np.mean(magnitude)

    # 归一化（经验值：5.0 像素/帧对应明显形变）
    return min(1.0, avg_magnitude / 5.0)
```

#### 4.2.3 形变事件判定

```python
NET_DEFORM_THRESHOLD = 0.4  # 形变量阈值（可配置）
NET_DEFORM_WINDOW    = 0.5  # 检测时间窗口（秒）

def detect_net_deformation_event(deform_scores: List[TimedScore]) -> List[Event]:
    """
    在形变量时间序列中检测显著形变事件。
    策略：滑动窗口内平均形变量超过阈值 → 触发事件
    """
    events = []
    for i, score in enumerate(deform_scores):
        window = get_window(deform_scores, i, NET_DEFORM_WINDOW)
        if np.mean([s.value for s in window]) >= NET_DEFORM_THRESHOLD:
            events.append(Event(timestamp=score.time, confidence=score.value))
    return deduplicate_events(events, min_gap=2.0)
```

**注意事项**：

- 篮板球争抢时篮网也可能晃动，单独依赖此信号误报率较高，必须与视觉轨迹联合使用
- 正式比赛模式下此信号权重设为 0，避免与 OCR 信号产生干扰

#### 4.3.2 分数识别与变化检测

```python
def detect_score_change(
    ocr_results: List[TimedScore]
) -> List[ScoringEvent]:
    """
    对比相邻帧的 OCR 识别结果，检测分数跳变。

    处理策略：
    - OCR 结果先经过噪声过滤（去除明显错误的识别结果）
    - 分数只能递增（篮球规则），逆向跳变为 OCR 错误
    - 跳变量为 1、2、3（1分/2分/3分球）时确认为进球
    - 跳变量为其他值时标记为疑似 OCR 错误，降低置信度
    """
    events = []
    for i in range(1, len(ocr_results)):
        prev_score = ocr_results[i-1]
        curr_score = ocr_results[i]
        delta = curr_score.home - prev_score.home  # 以主队为例

        if delta in (1, 2, 3):
            score_type = {1: 'free_throw', 2: 'two_pointer', 3: 'three_pointer'}[delta]
            events.append(ScoringEvent(
                timestamp=curr_score.time,
                score_type=score_type,
                confidence=0.95 if delta in (2, 3) else 0.85
            ))
    return events
```

### 4.4 音频分析（Pipeline D）

音频分析在两种模式下使用不同的检测策略。

#### 4.4.1 音频特征提取

```python
def extract_audio_features(audio_segment: np.ndarray, sr: int) -> AudioFeatures:
```

#### 4.4.2 正式比赛模式：欢呼声 + 解说激动度

```python
# 正式比赛音频检测目标
OFFICIAL_AUDIO_TARGETS = [
    'crowd_cheer',     # 观众欢呼声（音量激增 + 高频能量）
    'crowd_whistle',   # 裁判哨声
    'commentator_excite'  # 解说激动（语速加快，音调提高）
]
```

检测策略：
- 欢呼声：RMS 能量在 0.5 秒内激增超过 15 dB，且高频分量（2k~8kHz）占比超过 40%
- 解说激动度：使用预训练的音频分类模型（Mel + CNN）对 1 秒滑动窗口分类

#### 4.4.3 野球场模式：入网声 + 球友叫好声

```python
# 野球场音频检测目标
PICKUP_AUDIO_TARGETS = [
    'net_swish',       # 篮球入网的"刷"声（短促高频脉冲）
    'player_cheer',    # 球友叫好声（局部短时激励）
    'hand_clap'        # 击掌声
]
```

入网声（Swish）检测策略：
- 特征：持续时间短（50~200ms），高频分量为主（3k~10kHz），快速衰减
- 方法：滑动窗口能量检测，结合短时频谱形状匹配

> **局限**：音频检测在嘈杂环境（喧闹的场馆、室外噪音）下效果会显著下降，因此在两种模式下权重均不超过 0.15，作为辅助信号。

```python
def detect_shot_cuts(frames: List[Frame]) -> List[CutEvent]:
    """
    检测镜头切换（硬切/渐变）。
    方法：相邻帧直方图距离 > 阈值 → 硬切
    """
    events = []
    for i in range(1, len(frames)):
        hist_dist = compare_histograms(frames[i-1], frames[i])
        if hist_dist > CUT_THRESHOLD:
            events.append(CutEvent(timestamp=frames[i].time, type='hard_cut'))
    return events
```

## 五、多模态融合算法

### 5.1 时间轴对齐

各 Pipeline 的检测结果被对齐到统一的时间轴，以秒为单位，精度为 0.1 秒：

```python
def align_to_timeline(
    visual_events: List[Event],
    net_events:    List[Event],
    ocr_events:    List[Event],
    audio_events:  List[Event],
    scene_events:  List[Event],
    video_duration: float,
    resolution: float = 0.1  # 时间轴分辨率（秒）
) -> np.ndarray:
    """
    将各维度事件映射到统一时间轴，返回各维度的置信度时间序列。
    每个时间点的置信度 = 该时间点附近（±0.5s）最高事件置信度
    """
```

### 5.2 置信度融合

```python
WEIGHT_PRESETS = {
    'official': {
        'ocr':        0.40,
        'visual':     0.30,
        'net_deform': 0.00,
        'audio':      0.15,
        'scene':      0.15,
    },
    'pickup': {
        'ocr':        0.00,
        'visual':     0.70,
        'net_deform': 0.20,
        'audio':      0.10,
        'scene':      0.00,
    },
}

def fuse_confidence(
    visual_score:     Optional[float],
    net_deform_score: Optional[float],
    ocr_score:        Optional[float],
    audio_score:      Optional[float],
    scene_score:      Optional[float],
    scene_mode:       str = 'official'
) -> float:
    """
    根据场景模式动态选择权重，融合各维度置信度。
    None 表示该维度在当前帧未触发，不参与计算（权重归零处理）。
    """
    weights = WEIGHT_PRESETS[scene_mode]
    scores  = {
        'ocr':        ocr_score,
        'visual':     visual_score,
        'net_deform': net_deform_score,
        'audio':      audio_score,
        'scene':      scene_score,
    }

    total_weight = 0.0
    total_score  = 0.0

    for key, score in scores.items():
        w = weights[key]
        if score is not None and w > 0:
            total_weight += w
            total_score  += w * score

    if total_weight == 0:
        return 0.0

    fused = total_score / total_weight

    # 正式比赛：OCR 高置信度时给予额外加成（最可靠信号）
    if scene_mode == 'official' and ocr_score is not None and ocr_score > 0.8:
        fused = min(1.0, fused * 1.2)

    # 野球场：视觉轨迹 + 篮网形变双高置信度时给予额外加成
    if scene_mode == 'pickup':
        if (visual_score is not None and visual_score > 0.7 and
                net_deform_score is not None and net_deform_score > 0.7):
            fused = min(1.0, fused * 1.15)

    return fused
```

### 5.3 事件去重与合并

同一次进球可能被多个 Pipeline 在相近时间点各自检测到，需要合并为单一事件：

```python
DEDUP_WINDOW = 3.0  # 去重时间窗口（秒）

def deduplicate_events(events: List[FusedEvent]) -> List[GoalEvent]:
    """
    对时间相近的事件进行去重合并。
    策略：
    1. 按时间戳排序
    2. 相邻事件时间差 < DEDUP_WINDOW 则合并（取置信度最高的时间戳）
    3. 输出最终进球事件列表
    """
    if not events:
        return []

    events.sort(key=lambda e: e.timestamp)
    merged = [events[0]]

    for event in events[1:]:
        if event.timestamp - merged[-1].timestamp < DEDUP_WINDOW:
            # 合并：保留置信度更高的时间戳
            if event.confidence > merged[-1].confidence:
                merged[-1] = event
        else:
            merged.append(event)

    return merged
```

### 5.4 最终过滤

```python
CONFIDENCE_THRESHOLD = 0.5  # 最终置信度阈值（可配置）

def filter_events(events: List[GoalEvent], threshold: float = CONFIDENCE_THRESHOLD) -> List[GoalEvent]:
    """过滤低置信度事件，输出最终进球列表"""
    return [e for e in events if e.confidence >= threshold]
```

## 六、检测准确率目标

| 指标 | 目标值 | 说明 |
|------|--------|------|
| Precision（准确率） | ≥ 85% | 检测到的事件中真实进球的占比 |
| Recall（召回率） | ≥ 80% | 真实进球中被检测到的占比 |
| F1 Score | ≥ 82% | 准确率与召回率的调和平均 |
| 时间定位偏差（均值） | ≤ 1.0s | 检测时间戳与真实时间的平均偏差 |
| 时间定位偏差（P90） | ≤ 1.5s | 90% 的检测事件时间偏差 |

分场景目标：

| 场景 | Precision | Recall | F1 |
|------|-----------|--------|----|
| 正式比赛（有记分牌） | ≥ 92% | ≥ 88% | ≥ 90% |
| 野球场（无记分牌） | ≥ 80% | ≥ 75% | ≥ 77% |

## 七、已知局限与误判来源

### 7.1 视觉轨迹检测的误判场景

| 场景 | 误判类型 | 应对策略 |
|------|---------|---------|
| 篮下激烈对抗 | 误报（FP）：球在篮筐区域反复出现 | 严格几何判断（穿越内圈平面 + 方向向下） |
| 球被球员遮挡 | 漏报（FN）：追踪丢失 | ByteTrack 二阶段匹配补全轨迹 |
| 擦框未进 | 误报（FP）：球触筐弹出 | 连续 3 帧确认 + 冷静期机制 |
| 远景三分球 | 漏报（FN）：球体检测置信度低 | 降低远景场景的检测阈值（待优化） |
| 竖版视频 | 误报/漏报：ROI 区域计算偏差 | 视频旋转检测 + ROI 自适应调整 |

### 7.2 篮网形变检测的误判场景

| 场景 | 误判类型 | 应对策略 |
|------|---------|---------|
| 篮板球争抢 | 误报（FP）：碰框导致篮网晃动 | 权重低（0.20），与视觉轨迹联合判断 |
| 风吹/外力 | 误报（FP）：室外环境 | 引入基线运动量校准 |

### 7.3 音频分析的误判场景

| 场景 | 误判类型 | 应对策略 |
|------|---------|---------|
| 背景噪音 | 误报（FP）：噪音被误识别为欢呼/入网声 | 权重低（≤0.15），仅作辅助信号 |
| 多人同时发声 | 漏报（FN）：信号被掩盖 | — |

### 7.4 记分牌 OCR 的误判场景

| 场景 | 误判类型 | 应对策略 |
|------|---------|---------|
| 记分牌遮挡/切换 | 漏报（FN）：无法读取 | 结合视觉轨迹兜底 |
| OCR 误识别 | 误报（FP）：数字识别错误 | 分数只增不减的合法性校验 |

## 十一、当前实现状态与优化路线

> 本章基于 Phase 1 MVP 的实际代码（`ai-engine/detect.py`、`internal/ffmpeg/ffmpeg.go`、`configs/config.yaml`），对比上述目标架构，梳理差距并规划分阶段优化路径。

### 11.1 Phase 1 MVP 实现现状

Phase 1 已完成的 MVP 是一个**纯视觉、单维度、启发式**的进球检测方案，核心实现如下：

| 维度 | MVP 实际实现 | 目标架构（本文档设计） |
|------|-------------|---------------------|
| **目标检测模型** | YOLOv8n 预训练模型，检测 COCO class 32（sports ball）| 篮球专用模型，同时检测 basketball / hoop / net / player |
| **篮筐定位** | 硬编码 ROI：画面高度 15%~65% 范围 | YOLO 动态检测 hoop 目标，实时定位篮筐 |
| **目标追踪** | 无追踪器，仅帧间球位置比较 | ByteTrack 跨帧追踪，带 ID 的轨迹序列 |
| **进球判定** | 两种启发式规则：① 球在 ROI 连续出现后消失 ② 球 Y 坐标急剧下降 | 严格几何判断：球穿越篮筐内圈平面 + 方向向下 + 连续帧确认 |
| **篮网形变** | ❌ 未实现 | 光流法检测篮网 ROI 运动量 |
| **记分牌 OCR** | ❌ 未实现 | PaddleOCR 分数识别与跳变检测 |
| **音频分析** | ❌ 未实现；且集锦视频裁剪使用 `-an` 丢弃音轨 | 入网声 / 欢呼声 / 叫好声多目标检测 |
| **场景识别** | ❌ 未实现 | 自动识别正式比赛 / 野球场模式 |
| **多模态融合** | ❌ 仅单维度视觉 | 五维度加权融合 + 动态权重 |
| **置信度阈值** | 0.3（过低，导致误报偏多） | YOLO 0.5，最终融合阈值 0.5 |

### 11.2 核心差距分析

基于 GoalCut **野球场/业余比赛自动集锦**的产品定位，对当前 MVP 与目标架构的差距按影响程度排序：

#### 差距 1：硬编码 ROI — 最大准确率瓶颈 🔴

```python
# 当前代码 (detect.py L141-142)
hoop_y_min = img_h * 0.15
hoop_y_max = img_h * 0.65
```

**问题**：野球场拍摄角度多变（高位/低位/侧面），固定比例 ROI 在非标准机位下会严重偏移，导致大量漏检和误判。

**影响**：Precision/Recall 均受限，预估当前准确率仅 50~60%，远低于目标 80%+。

#### 差距 2：无目标追踪 — 进球判定逻辑脆弱 🔴

当前仅做帧间球位置比较，无法：
- 区分多个球体（野球场常有多个球）
- 在遮挡后重新关联同一球体
- 构建完整抛物线轨迹用于几何判定

#### 差距 3：集锦无音频 — 体验缺失 🟡

```go
// 当前代码 (ffmpeg.go L158)
"-an",  // 丢弃音轨
```

**问题**：集锦视频完全没有声音，对于野球场场景（球友叫好、入网声）严重影响观看体验。

#### 差距 4：置信度阈值过低 — 误报偏多 🟡

```yaml
# 当前配置 (config.yaml)
confidence_threshold: 0.3
yolo_confidence: 0.3
```

**问题**：0.3 的阈值使得大量低质量检测结果被当作进球候选，误报率高。

#### 差距 5：无篮网形变 / 音频辅助 — 缺少野球场差异化信号 🔵

野球场模式下，篮网形变（权重 0.20）和入网声（权重 0.10）是重要辅助信号，当前完全缺失。

### 11.3 优化项与优先级

根据**成本收益比**（准确率提升 / 开发成本），将优化项分为三个优先级：

#### P0 — 快速见效（预计 4h，不改架构）

| 编号 | 优化项 | 改动 | 预期效果 |
|------|--------|------|---------|
| O-1 | **集锦保留音频** | `ffmpeg.go` 移除 `-an` 参数，改为 `-c:a aac` | 集锦有声音，体验大幅提升 |
| O-2 | **提高置信度阈值** | `config.yaml` 中 `confidence_threshold` 调至 0.5，`yolo_confidence` 调至 0.4 | 减少误报，Precision 预估提升 10~15% |

#### P1 — 核心提升（预计 40h，改进检测架构）

| 编号 | 优化项 | 改动 | 预期效果 |
|------|--------|------|---------|
| O-3 | **动态篮筐检测** | 在 YOLO 检测中增加 hoop 类别（使用开源篮球数据集微调或 Roboflow 预训练权重），替代硬编码 ROI | **最关键优化**，Recall 预估提升 20%+ |
| O-4 | **基于空间几何的进球判定** | 实现本文档 4.1.3 节的 `judge_goal_by_trajectory` 算法：球穿越篮筐平面 + 方向向下 + X 坐标在内圈范围 | Precision 预估提升 15%，有效排除"球在篮筐附近但未进"的误判 |
| O-5 | **简单 IOU 追踪器** | 实现轻量级 IOU Tracker（不需要完整 ByteTrack），为篮球建立帧间关联，输出带 ID 的轨迹 | 配合 O-4 提供连续轨迹输入，处理多球/遮挡场景 |
| O-6 | **冷静期机制** | 实现进球确认后 2 秒冷静期，防止同一进球被重复计数 | 减少重复事件，Precision 提升 |

#### P2 — 差异化增强（预计 30h，多模态扩展）

| 编号 | 优化项 | 改动 | 预期效果 |
|------|--------|------|---------|
| O-7 | **篮网形变检测** | 实现本文档 4.2 节的 Pipeline B：光流法计算篮网 ROI 运动量 | 野球场模式下提供 0.20 权重的辅助信号 |
| O-8 | **入网声（Swish）检测** | 提取音频轨道，使用 Mel 频谱 + 短时能量检测短促高频脉冲 | 野球场安静环境下的独特辅助信号 |
| O-9 | **两阶段采样** | 第一遍低帧率（2fps）粗扫 → 锁定候选区间 → 第二遍高帧率（8fps）精确检测 | 在不增加总耗时的情况下提高时间定位精度 |
| O-10 | **篮球专用 YOLO 模型** | 收集/标注篮球场景数据集，微调 YOLOv8 检测 basketball/hoop/net/player 四类 | 从根本上提升检测精度，配合动态篮筐检测 |
