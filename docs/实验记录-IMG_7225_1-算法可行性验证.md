### 2. 这四轮已经证明了什么

#### 2.1 粗扫阶段已经证明“有解”

- 首轮粗扫仅靠现有 1a/1b 通道只能召回 `2/3` 个 GT 进球
- 二轮加入**运动突变通道 + 候选去重**后，粗扫召回率稳定达到 **100%**
- 三、四轮保持不回退，说明**候选生成不再是当前主瓶颈**

**阶段性结论**：

> 粗扫上游的方向是正确的，后续可以把更多精力从“能否召回”转移到“如何减少假候选”和“如何让精扫真正吃到有效输入”。

#### 2.2 篮筐区域修复是首个关键拐点

首轮的主阻塞不是判定逻辑本身，而是：

- YOLO 检出的 `hoop bbox = 33px`
- 远小于自适应估算的 `134px`
- 导致所有“篮筐附近”门控几乎全部失效

二轮将有效区域扩大后，系统结构性变化非常明显：

- 篮筐附近片段：`0 -> 18`
- 关键区连续追踪率：`0% -> 32.7%`
- 消失-重现开始产出候选：`0 -> 21`

**阶段性结论**：

> 首轮失败不能用来否定算法主线，因为精扫阶段当时几乎没有拿到正确的近篮筐观测输入。二轮证明了：只要修复观测窗口，后续通道才有机会真正被检验。

#### 2.3 跨轨迹消失-重现是目前第一条真正跑通的有效子路径

三轮新增跨轨迹分析后首次出现：

- `TP = 1`
- `FP = 2`
- `FN = 2`
- `F1 = 0.33`

四轮进一步收紧条件后：

- `TP` 保持 `1`
- `FP` 从 `2 -> 1`
- `Precision` 从 `0.33 -> 0.50`
- `F1` 从 `0.33 -> 0.40`

这说明：

- 该路径不是随机撞中，而是确实捕捉到了真实进球的时序模式
- 假阳性是可压缩的，至少一部分 FP 能通过更强前置条件被消除

**阶段性结论**：

> 当前系统真正被真实视频验证成功的，不是“连续追踪 + 残差主线”，而是**跨轨迹消失-重现**这条子路径。

### 3. 这四轮还没有证明什么

#### 3.1 还没有证明“近篮筐连续追踪主线”已经可用

虽然二轮后出现了 `32.7%` 的关键区连续追踪率，但这个数字还不能直接解释为“防线 1 可用”，原因是：

- `sigma_pos` 从 `16.89px` 上升到 `41.75px`
- 说明扩大有效区域后，虽然拿到了更多近篮筐片段，但同时也混入了更多**错误关联 / 错误目标 / 轨迹漂移**
- 因此当前的连续追踪片段数量**不等于**高质量连续追踪片段数量

**阶段性结论**：

> 防线 1 已经从“无输入”进入“可验证状态”，但还远未达到“已验证成功”的程度。

#### 3.2 还没有证明“抛物线拟合残差”已能稳定排除打铁

从四轮记录看：

- 残差计算框架能跑通
- 也能看到 `P50`、`P90`、`max` 等统计量
- 但尚未形成“空心 / 擦筐 / 打铁 / 打板”在**篮筐附近真实样本**上的分布分离证据

尤其首轮、二轮里的高残差，很可能有相当一部分来自：

- IOUTracker 错误关联
- 多目标切换
- 漂移轨迹

而不是真实碰撞本身。

**阶段性结论**：

> 当前最多只能说“残差模块技术上已跑通”，还不能说“残差主线在真实视频上已被实证证明成立”。

#### 3.3 还没有证明三道防线已经形成稳定互补

当前真正产生有效输出的是：

- **粗扫候选召回**
- **跨轨迹消失-重现**

而以下通道仍未形成稳定贡献：

- 近篮筐连续追踪下的残差/方向变化
- 反证法
- 多通道融合后的稳定判定

**阶段性结论**：

> 当前系统已经找到一条“能出 TP 的路径”，但还没有达到“三道防线互补成熟”的状态。

### 4. 当前主瓶颈的收敛结论

四轮数据已经把系统瓶颈从“整体不行”收敛成了两个非常具体的问题：

#### 4.1 第一主瓶颈：篮筐附近球观测质量不足

表现为：

- 14s、64s 两个 GT 都不是被最终规则排除，而是**关键处没看到球**
- 64s 甚至出现“篮筐处完全没检测到球，只在下方看到球”的情况
- 这类样本不是调规则能解决的，需要提升**球检测覆盖率 / 近篮筐观测质量**

#### 4.2 第二主瓶颈：追踪器关联质量不足

表现为：

- `sigma_pos` 异常偏高
- 关键区连续追踪率长期卡在 `32.7%`
- 高残差中夹杂大量潜在伪异常

**收敛判断**：

> 当前系统的上限，不是被“规则是否合理”卡住，而是被“关键处能否看到球、能否把它稳定追对”卡住。

### 5. 三个 GT 样本分别说明了什么

| GT 样本 | 当前状态 | 最主要信息 |
|--------|---------|-----------|
| **14s** | 最终仍漏检 | 粗扫可修复，但窗口内球检测/追踪碎片化严重 |
| **64s** | 最终仍漏检 | 篮筐处球体检测覆盖明显不足，属于“观测缺失型”失败 |
| **93s** | 三、四轮稳定 TP | 证明跨轨迹消失-重现路径在真实视频上是成立的 |

这说明当前系统面对的不是单一问题，而是至少已经分化成两类：

1. **可由跨轨迹消失-重现识别的进球**（如 93s）
2. **必须依赖更强球检测或非球体证据的进球**（如 14s、64s）

### 6. 对当前路线的阶段性判断

#### 可以确认继续投入的部分

- 粗扫候选生成
- 篮筐区域自适应修复
- 跨轨迹消失-重现检测
- 假阳性通过前置条件约束进行压缩

#### 仍需谨慎，不应过早定型的部分

- 残差阈值
- `judge_goal_by_continuity` 穿越条件
- 反证法前置门控
- 多通道融合权重/逻辑

原因很简单：

> 在关键处球观测质量不足、追踪关联质量不稳之前，继续大幅调这些规则，很容易变成“用规则去适配噪声”。

### 7. 下一阶段最合理的优先级

基于四轮趋势，下一阶段不建议再优先做“更复杂的判定规则”，而应按如下顺序推进：

1. **先修近篮筐球观测质量**
   - 提升 YOLO 对篮筐附近球体的检测覆盖
   - 重点解决 14s / 64s 这类“关键处没看到球”的问题

2. **再修追踪器关联质量**
   - 降低 `sigma_pos`
   - 把“关键区连续追踪率”从 `32.7%` 推到接近 `60%` 通过线

3. **然后重新验证防线 1**
   - 在高质量近篮筐轨迹上重新观察残差分布
   - 这时再判断 `3σ / 2σ` 是否有意义

4. **最后才做融合定型**
   - 在单通道输入质量稳定后，再决定反证法门槛和融合逻辑

### 8. 最终阶段性结论

如果只基于这四轮数据，最准确的结论不是“算法已经可用”，也不是“算法失败”，而是：

> **当前系统已经成功从“零有效输出”推进到“存在稳定 TP 的原型状态”，并明确证明了跨轨迹消失-重现这条子路径可行；但整体系统的上限仍被“篮筐附近球检测覆盖不足 + 追踪关联质量不足”这两个观测层问题卡住。**

换句话说：

- **方向没错**
- **系统在变好**
- **真正的主瓶颈已经收敛出来了**
- **下一步应先修观测质量，再谈规则定型**

## 第五轮实验计划：近篮筐球检测专项验证

### 1. 目标

第五轮实验只聚焦一个主问题：

> **提升篮筐附近球体的检测覆盖率，让 14s / 64s 这类“关键处看不到球”的样本，至少在近篮筐时刻能够形成有效观测。**

本轮**不以最终 F1 为首要目标**，而以“观测层是否被修通”为首要目标。

### 2. 为什么第五轮先做这个

基于前四轮数据，当前系统已经确认：

- 粗扫召回率已到 `100%`
- 跨轨迹消失-重现已经产生稳定 TP
- 但 14s / 64s 漏检仍然来自**篮筐附近球观测缺失**
- `sigma_pos` 偏高也说明追踪器正在吃到质量较差的输入

因此第五轮如果继续优先调：

- 融合逻辑
- 反证法门槛
- 更复杂的跨轨迹规则

大概率只是在“用规则适配噪声”，无法实质提升系统上限。

### 3. 本轮只改动什么

建议本轮只允许改动以下三类内容之一，避免变量过多：

#### 方案 A：只调现有检测推理参数（最低成本）

- 提高 `imgsz`
- 在篮筐 ROI 内降低球检测 `confidence threshold`
- 适当放宽近篮筐区域的小目标 NMS/阈值

#### 方案 B：加入二阶段近篮筐 ROI 检测（中成本）

- 全图先检测篮筐
- 以篮筐为中心裁剪 ROI
- 对 ROI 放大后再次跑球检测
- 将 ROI 检测结果映射回原图坐标

#### 方案 C：做近篮筐球检测小样本微调（较高成本）

- 抽取 200~500 帧近篮筐关键帧
- 只标注球 bbox
- 基于现有 `basketball_v1` 做轻量微调

> **建议顺序**：先 A，再 B，最后才考虑 C。除非 A/B 已明确无效，否则不要直接上微调。

### 4. 本轮明确不改什么

- 不改融合逻辑
- 不改反证法规则
- 不改 `judge_goal_by_continuity` 的核心判定哲学
- 不改残差阈值 `3σ / 2σ`
- 不改跨轨迹匹配主逻辑（除非用于适配新的检测输出格式）

### 5. 最小数据集建议

本轮不是做全量评测，而是做**近篮筐球检测专项验证**。建议最小样本如下：

| 样本类型 | 建议数量 | 目的 |
|---------|---------|------|
| 14s 附近关键帧 | 50~100 帧 | 验证关键处漏检是否可补回 |
| 64s 附近关键帧 | 50~100 帧 | 验证篮筐处完全无球检测的问题 |
| 93s 附近关键帧 | 50~100 帧 | 作为已成功样本对照 |
| 非进球但近篮筐球帧 | 50~100 帧 | 防止只提升召回却引入大量 FP |
| 其他篮筐附近遮挡帧 | 50~100 帧 | 验证遮挡条件下的增益 |

> **建议总量**：先做 200~500 帧，不追求大规模，优先追求“关键位置覆盖”。

### 6. 第五轮的通过线（只看观测层）

本轮不要先盯最终 F1，而是只看以下 4 个指标：

## 第五轮/第六轮联合分析与第七轮建议

### 1. 两轮联合趋势总结

第五轮和第六轮可以视为一个连续的“两阶段修复过程”：

- **第五轮**解决的是“关键处看不到球”
- **第六轮**解决的是“看到了，但太乱、误报太多”

从趋势上看，这两轮共同把系统从“存在单一路径 TP”推进到了“在单视频上达到原型可用”：

| 维度 | 第四轮 | 第五轮 | 第六轮 | 联合解读 |
|------|-------|-------|-------|---------|
| 近筐球检测覆盖率 | 极低/未系统统计 | **55%** | **51%** | 第五轮开始把观测层真正打通，第六轮在略牺牲覆盖的情况下换来更高质量 |
| 关键区连续追踪率 | 32.7% | 44.6% | 40% | 说明追踪质量开始可控，但仍未达到防线1的稳定验证线 |
| `sigma_pos` | 41.75px | **61.74px** | **29px** | 第五轮“看到更多但更乱”，第六轮成功把噪声拉回可用区间 |
| Recall | 0.33 | **1.00** | **1.00** | 第五轮首次补齐全部 GT，第六轮未回退，说明召回已打通 |
| Precision | 0.50 | 0.21 | **0.50** | 第五轮召回突破但误报失控，第六轮通过质量门控修复 |
| F1 | 0.40 | 0.35 | **0.67** | 第六轮首次进入“可继续外推验证”的状态 |

### 2. 已经可以比较有把握确认的结论

#### 2.1 当前最成熟的主路径是“跨轨迹消失-重现 + 质量门控”

第六轮 3 个 GT 的命中通道全部来自：

- **14s**：跨轨迹
- **64s**：跨轨迹
- **93s**：跨轨迹

这说明当前真正被实证跑通的不是“高质量连续追踪 + 残差主判定”，而是：

> **跨轨迹消失-重现** 在真实视频上已经具备稳定工作能力，并且在加上质量门控后，可将误报控制到可接受区间。

#### 2.2 第五轮和第六轮共同证明：主瓶颈确实在观测层

- 第五轮一旦提升近筐球检测覆盖率，`Recall` 就直接从 `0.33 -> 1.00`
- 第六轮通过追踪质量约束，`Precision` 又从 `0.21 -> 0.50`

这条因果链非常清楚：

> **当前系统性能上限首先取决于“关键位置有没有球、球能不能被稳定跟住”，其次才轮到规则本身。**

#### 2.3 第六轮的 `F1=0.67` 是里程碑，但不是终局证明

第六轮说明当前路线绝对值得继续投入，但它成立的前提仍然很窄：

- 仅在 **1 个视频** 上验证
- GT 数仅 **3 个**
- 成功路径高度依赖当前视频中的跨轨迹时序模式

因此这个结果更适合定义为：

> **单视频原型里程碑达成**，而不是“算法已普适成立”。

### 3. 第五轮/第六轮之后仍未解决的关键问题

#### 3.1 防线 1 仍未被独立证明成立

虽然第六轮已经把 `sigma_pos` 压到 `29px`，但仍存在三点不足：

- 关键区连续追踪率只有 `40%`，仍低于文档目标线 `60%`
- 还没有拿到“空心 / 擦筐 / 打铁 / 打板”在近筐残差上的分离证据
- 当前 3 个 GT 的命中，并不是由残差主线完成的

**结论**：

> 当前不能因为总体 F1 提升，就宣称“运动学残差主线已被验证成功”。

#### 3.2 FP 结构已经变得可分析，但还未沉淀成正式误差分类

第六轮剩余 3 个 FP 分别对应：

- 同轨迹消失-重现误判
- 穿越判定误判
- 篮下落球误判

这说明系统误差已经从“随机失控”进入“结构化误差”阶段。下一步应把这些 FP 明确沉淀成规则库或误差 taxonomy，而不是继续凭感觉调阈值。

#### 3.3 当前外推性仍未知

第五轮/第六轮的数据足以证明：

- 这条路线在 `IMG_7225_1.mp4` 上是能工作的

但还不能证明：

- 它在其它 Q-PARK 视频上仍然成立
- 它在不同场地、不同机位、不同压缩率视频上还能保持相似表现

### 4. 第七轮最合理的目标，不是继续压单视频 F1

基于当前状态，第七轮**不建议**把目标设成：

- “把 F1 从 0.67 提到 0.75”
- “再压一两个 FP”
- “再调一点融合权重”

因为这样很容易走向**单视频过拟合**。

第七轮更合理的目标应是：

> **验证第六轮主路径是否具备外推性，并开始独立验证防线 1。**

### 5. 第七轮建议：拆成两条并行子任务

#### 子任务 A：多视频外推验证（优先级最高）

目标：验证“跨轨迹消失-重现 + 质量门控”是否只是在当前单视频有效，还是在同类视频中普遍成立。

**建议数据**：

| 类型 | 建议数量 | 目的 |
|------|---------|------|
| 同场地同机位视频 | 3~5 条 | 先验证是否能跨视频复现当前结论 |
| 同场地不同时间视频 | 2~3 条 | 观察光照、噪声、人员密度变化影响 |
| 不同场地固定机位视频 | 2~3 条 | 粗看外推能力 |

**第七轮-A 核心指标**：

- 候选窗口召回率
- 事件级 Recall / Precision / F1
- 跨轨迹通道命中率
- FP 类型分布是否与当前视频一致

**通过标准（建议）**：

- 至少 3 条额外视频中，主路径能重复产出 TP
- 平均 Recall 不显著退化
- Precision 不出现系统性崩塌

#### 子任务 B：防线 1 独立验证支线

目标：不要再混在总 F1 里看，而是单独验证“残差主线到底有没有真实解释力”。

**建议做法**：

- 只筛选“近篮筐有连续轨迹”的片段
- 人工按类别分成：空心 / 擦筐 / 打铁 / 打板
- 单独统计这些片段的：
  - `sigma_pos`
  - 残差均值 / P50 / P90 / max
  - 方向翻转率
  - 近筐持续帧数

**第七轮-B 关注问题**：

1. 打铁片段的残差是否显著高于空心片段？
2. 擦筐片段是否真的落在“残差边界区”？
3. `3σ / 2σ` 是否还有保留价值，还是要改成别的门控？

### 6. 第七轮明确不建议优先做的事

在完成第七轮 A/B 之前，建议**不要优先**：

- 大改融合权重
- 引入更多复杂规则分支
- 继续围绕单视频做大规模阈值微调
- 直接宣称三道防线已经全部成立

原因：

> 现在最缺的不是“单视频更高分”，而是“知道第六轮结论到底能不能外推、知道防线1到底是否真的成立”。

### 8. 最终建议

如果你只允许做一件事，我建议第七轮优先做：

- 还是一个**场景级可复用解**
