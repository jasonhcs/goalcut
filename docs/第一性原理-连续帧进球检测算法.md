## 一、核心命题

### 1.1 从第一性原理定义"进球"

> **进球的物理本质：篮球完整地从上方穿过篮筐（篮网），且在穿越过程中未被弹回。**

这个定义包含三个不可约的约束：

1. **方向约束**：球必须从上方进入篮筐（从下方穿过不算）
2. **完整性约束**：球必须完整通过（卡在篮筐上不算）
3. **几何约束**：篮筐是固定的水平圆环（直径 ~45cm），球直径 ~24cm

### 1.2 关键洞察：进球是时序因果事件，不是瞬间空间状态

传统方法试图在**某一帧**中判断"球是否在篮筐内"——这是一个非常难的空间推断问题（需要3D信息）。

第一性原理的洞察是：

> **进球不是一个瞬间状态，而是一个时序因果事件。它有明确的"开始→过程→结束"，在视频的连续帧中留下不可伪造的时序签名。**

因此，正确的问法不是"球在不在篮筐里"，而是：

> **"球的整个运动生命周期，是否讲述了一个'进球的故事'？"**

### 1.3 进球 = "运动轨迹没有不连续偏离"

> ⚠️ **v1.5 修正**：原标题为"进球 = 加速度没有突变"。经 9.4 节验证，二阶差分加速度在 YOLO 噪声下 SNR < 1.0，工程不可用（G-2）。经 R-1 评审确认，核心原理修正为"轨迹连续性"——本质相同，度量方式从不可用的"逐帧加速度绝对值"改为可行的"抛物线拟合残差"。

从连续性分析得到的最深层原理：

| 场景 | 轨迹偏离特征 | 运动方向特征 |
|------|-------------|------------|
| **空心球（Swish）** | 全程符合抛物线，拟合残差 ≈ σ_pos | 球始终向下运动，vy 无符号翻转 |
| **擦筐进球** | 有**小幅**偏离，残差略增但球仍向下 | vy 可能短暂减小但不变号 |
| **打铁弹出** | 有**剧烈**偏离，残差 >> σ_pos | 球方向反转，vy 符号翻转 |
| **打板进球** | 碰篮板时偏离，之后恢复抛物线向下 | 碰板后方向变化，再恢复向下穿筐 |

> **核心规律：不管之前发生了什么碰撞，关键看最后阶段——球在穿过篮筐平面的那一刻，是否有一段"平滑的向下运动"，且之后没有反弹回来。**
>
> **工程度量方式**：
> - **主要手段**：抛物线拟合残差（打铁 SNR ≈ 51~69，擦筐 SNR ≈ 3~7） + 速度方向变化（vy/vx 符号翻转）
> - **已弃用**：二阶差分逐帧加速度绝对值（SNR < 1.0，见 G-2）

## 二、核心理论框架（Theory Overview）

> 本章是全文的理论总纲。将散布在各章的第一性原理推导、验证修正、评审结论凝练为一个完整的理论体系，供快速理解全局。
>
> 详细推导见第三~五章，验证数据见第九章，评审修正见第十二章。

### 2.1 一句话定义

> **进球 = 球的运动轨迹在穿过篮筐平面时没有发生不连续偏离，且之后没有被弹回。**

这是经评审修正后的最终表述（原文"进球 = 加速度无突变"在工程上不可直接度量，见 R-1）。

### 2.2 三条不可约的物理公理

| 编号 | 公理 | 形式化 | 来源 |
|------|------|--------|------|
| **A1** | 进球是时序因果事件，不是瞬间空间状态 | 必须分析连续帧序列，而非单帧 | 1.2 节 |
| **A2** | 自由飞行的球在图像中近似表现为平滑抛物线；碰撞会导致轨迹偏离该平滑模型 | 无碰撞：残差 ≈ σ_pos；碰撞：残差显著升高 | 1.3 节 + R-1 修正 |
| **A3** | 进球后球不会从篮筐上方/侧方逃逸；不进球通常出现弹回、侧向逃逸或未完成穿越 | 穿筐后观察窗口内不存在向上翻转、侧向逃逸、上方重现中的任一强证据 | 1.3 节 |

### 2.3 核心检测策略（三道防线）

从公理推导出三种互补的检测手段，覆盖不同信息可用性场景：

```
防线 1                    防线 2                    防线 3
轨迹连续性分析            消失-重现模式匹配          反证法（无弹回证据）
━━━━━━━━━━━━━━━         ━━━━━━━━━━━━━━━━         ━━━━━━━━━━━━━━━━
前提: 球可连续追踪        前提: 球在篮筐区被遮挡     前提: 碰撞后仍有观测
      (碰撞前 ≥5帧)            (消失 ≥2帧)               (覆盖率 ≥50%)

方法: 抛物线拟合残差      方法: 消失角度/速度 +      方法: 搜索弹回信号
      + 速度方向变化            重现位置/速度/方向          (vy翻转/侧向逃逸)
      + 碰撞序列模式            + 时间间隔匹配

输出: 打铁排除 /            输出: 进球/打铁模式        输出: 有弹回 → 排除
      连续性支持                  证据分 0.75               无弹回 → 支持(≤0.45)
      证据分 0.80~0.95

适用: 球在空中飞行        适用: 球穿筐过程被挡       适用: 任何遮挡场景
      (阶段 A)                 (阶段 B)                  (阶段 B 兜底)
```

三道防线覆盖了进球事件的完整生命周期：

```
[出手] ──── 飞行(0.5~1.5s) ────→ [接近篮筐] ── [碰撞/穿筐] ── [落下]
                                       │              │            │
                                   防线1:拟合       防线2:消失    防线3:反证
                                   残差分析         重现模式      无弹回检查
```

### 2.4 关键物理常数与约束

| 参数 | 值 | 来源 | 验证状态 |
|------|-----|------|---------|
| 篮筐直径 | 0.4572m | NBA/FIBA 标准 | — |
| 球直径 | 0.2426m (7号球) | NBA 标准 | — |
| 球穿越篮筐平面时间 | **0.05 ~ 0.4s**（典型 0.05~0.25s） | 抛物线运动方程 | ✅ P1 验证通过（修正） |
| 消失-重现时间窗口 | **0.06 ~ 1.0s** | 穿筐+穿网+遮挡延迟 | ✅ P5 验证通过（修正） |
| 精扫最低帧率 | **24fps**（推荐 30fps） | 穿越帧数 ≥ 1.3 | ✅ 采样率验证通过 |
| 像素空间重力 | `g_px = 9.81 × (hoop_w_px / 0.4572) / fps²` | 单目尺度推断 | ✅ 量纲正确；适用于近似单目尺度场景 |

> **建模前提（必须显式成立）**：
> 1. 本文默认普通针孔相机近似成立，篮筐区域内透视变化有限；
> 2. 球在接近篮筐的局部时间窗内可近似视为二维投影下的平滑轨迹；
> 3. 空气阻力、旋转导致的 Magnus 效应、镜头畸变、滚动快门等二阶因素在本版本中**未显式建模**，只通过残差裕量和适用范围约束间接吸收；
> 4. 文中 `confidence` / `score` 一律指**未校准证据分**，用于排序和融合，**不是严格概率**；若要输出概率，需在标注集上做后验校准（如 Platt / Isotonic）。

### 2.5 碰撞检测：工程可行的方法（评审修正）

原文提出的"二阶差分加速度突变"在理论上正确，但 **YOLO 检测噪声经二阶差分放大后 SNR < 1.0，工程上完全不可用**（G-2 问题，9.4 节验证）。

经评审（R-1）及二轮验证确认，**替代方案可行**：

| 方法 | 原理 | SNR | 可行性 | 角色 |
|------|------|-----|--------|------|
| ~~二阶差分加速度~~ | ~~逐帧加速度绝对值~~ | ~~< 0.001~~ | ~~❌ 不可用~~ | ~~弃用~~ |
| **抛物线拟合残差** | 拟合 N 帧抛物线，残差大 = 碰撞 | 打铁 51~69 / 擦筐 3~7 | ✅ 主要手段 | **排除打铁**（非区分所有碰撞类型） |
| **速度方向变化** | vy/vx 符号翻转 = 弹回 | N/A（布尔判断） | ✅ 主要手段 | 弹回检测 |
| 多帧一致性 | 连续 N 帧异常才触发 | — | ✅ 辅助 | 降低假阳性 |

> ⚠️ **v1.5 重要修正（N-1）**：拟合残差碰撞检测的角色应定位为"**排除打铁**"而非"区分所有碰撞类型"。原因：
> - 打铁弹出残差 ≈ 58~78px，SNR 51~69，**可靠检测** ✅
> - 擦筐微扰残差 ≈ 4~8px，SNR 3~7，**处于检测边缘** ⚠️（碰撞持续 10~20ms 在 30fps 下仅 0.3~0.6 帧）
> - 擦筐进球不需要碰撞检测来判定——球最终穿过篮筐平面且 vy 不翻转，由穿越检测 + 消失-重现分析覆盖
> - 因此：**检测到大残差 → 排除打铁；未检测到大残差 → 可能空心球或擦筐进球，两者都是进球**

关键区别：
- 二阶差分计算**逐帧加速度绝对值** → 对噪声极度敏感（放大 √6/dt² ≈ 2200 倍）
- 抛物线拟合计算**轨迹偏离模型的程度** → 多帧平均抑制噪声（√N 倍）

### 2.6 信号层次与退化策略

不同信息可用性下，算法自动退化到可用的最高精度层次：

```
层次 1 (最高精度):  球可追踪 + 篮网可见 → 轨迹分析 × 篮网形变 交叉验证
                   证据分上限: 0.95

层次 2:            球可追踪 + 篮网不可见 → 轨迹分析 + 消失-重现
                   证据分上限: 0.85

层次 3:            球不可追踪 + 篮网可见 → 纯篮网形变检测
                   证据分上限: 0.90

层次 4:            球偶现 + 篮网偶现 → 消失-重现 + 反证法
                   证据分上限: 0.65

层次 5 (最低精度):  都不可见 → 球员反应（庆祝/回防）+ 音频
                   证据分上限: 0.50
```

### 2.7 适用范围与已知边界

| 维度 | 适用范围 | 不适用 / 需特殊处理 |
|------|---------|-------------------|
| **投篮类型** | 投篮（罚球/中投/三分） | 上篮（飞行段短，大概率退化到防线2/3）；扣篮（非自由飞行，需走专用分支，见 R-8） |
| **视频帧率** | ≥ 24fps（运动学分析）；≥ 15fps（退化到消失-重现） | < 15fps（仅篮网形变 + 启发式可用） |
| **视角** | 水平偏移 ≤ 30°（g_pixel 误差 ≤ 15%） | 偏移 ≥ 45°（需视角校正，见 R-5）；仰角 > 15° 时 vy 方向判定精度下降 |
| **多球** | 独立追踪各球，分别判定 | 极近距离多球交叉（追踪器 ID 混淆，见 R-10） |
| **追踪连续性** | 碰撞前 ≥ 5 帧连续追踪 | 全程碎片化（退化到消失-重现 + 反证法，见 R-3） |
| **拍摄方式** | 三脚架/固定机位（篮筐画面位置稳定） | 手持拍摄（需逐帧篮筐追踪或全局运动补偿，见 N-2） |

> ⚠️ **v1.5 新增边界声明**：
> 1. **上篮场景**：飞行段极短（~0.3s = 9帧），运动学分析（防线1）大概率无法获得 ≥5 帧连续追踪，应预设退化到防线2（消失-重现）和防线3（反证法）
> 2. **手持拍摄**：篮筐在画面中位置随相机运动持续变化，"粗扫锁定篮筐位置"策略失效，需逐帧检测篮筐或做全局运动补偿
> 3. **擦筐碰撞**：拟合残差碰撞检测对擦筐的 SNR 处于边缘（3~7），擦筐进球主要由"穿越后仍向下"正向判定，不依赖碰撞检测
> 4. **无网 / 铁链网 / 破损篮网**：会显著改变穿网耗时和篮网形变模式，防线2的时间窗口与防线4的网形证据需单独校准
> 5. **球在筐上滚动、多次颠筐、Wedgie（卡板卡筐）**：不应被简单压缩到"进/不进"二分类，建议输出"非常规事件/证据不足"
> 6. **超广角 / 鱼眼 / 强变焦 / 剧烈平移旋转拍摄**：二维抛物线近似可能失效，应降级或拒绝使用防线1
> 7. **规则语义边界**：本文面向视频事件识别，不直接覆盖干扰球、圆柱体规则等裁判规则判罚语义

## 三、多通道证据体系（按可靠性排序）

从第一性原理出发，进球这个物理事件会在视频中留下多种可观测信号。按可靠性和互补性排列：

### 3.1 直接物理证据

| 信号 | 物理原理 | 可靠性 | 检测条件 | 对应现有通道 |
|------|---------|--------|---------|------------|
| **篮网形变** | 球穿网时篮网产生"鼓包-收缩-摆动"序列 | ★★★★★ | 篮网必须可见 | 通道 4（有向光流） |

### 3.2 间接因果证据

## 四、连续帧扫描算法——逐帧运动学分析

### 4.1 核心思想：每帧都不能跳过

> **必须对视频的每一帧进行扫描，保证连续性。**

原因：
- 球穿越篮筐平面的物理时间约 0.05~0.4 秒（典型场景 0.05~0.25s，见第九章验证）
- 在 30fps 视频中，这仅对应 1.8~12 帧（典型场景 1.8~7.5 帧）
- 在 3fps 采样下，穿越事件极大概率被完全跳过（所有场景均 < 1 帧）
- **任何跳帧采样都会破坏连续性分析的基础**

### 4.2 两阶段全帧扫描策略

为了兼顾效率和连续性，采用**两阶段策略**：

```
阶段1（粗扫）: 低频采样（~3fps），锁定候选时间窗口
    │
    │  目的：定位"可能发生进球"的时间区间
    │  方法：篮筐区域运动检测、音频突变、人体运动
    │  输出：候选区间列表 [(t_start, t_end), ...]
    │
    ▼
阶段2（全帧精扫）: 候选区间内逐帧扫描（原始帧率，30fps）
    │
    │  目的：对每个候选区间做逐帧运动学分析
    │  方法：连续帧加速度分析、轨迹连续性验证
    │  关键：frame_step = 1，不跳过任何帧
    │
    ▼
输出：精确的进球事件列表
```

### 4.3 逐帧运动学变量计算

> **坐标系约定（全文统一）**：
> - 原点：图像左上角
> - x 轴：向右为正
> - y 轴：向下为正
> - 因此：`vy > 0` 表示球向下运动，`vy < 0` 表示球向上运动
> - 重力方向：`+y`

对候选区间内的每一帧，计算以下运动学量：

```python
def compute_kinematics(track: List[TrackPoint], dt: float) -> KinematicsSequence:
    """
    对球的追踪序列计算逐帧运动学变量。

    输入:
        track: [(x₁,y₁,t₁), (x₂,y₂,t₂), ...] 球的逐帧位置
        dt: 帧间隔 (1/fps)

    输出:
        KinematicsSequence: 包含每帧的位置、速度，以及仅供诊断使用的加速度

    说明:
        - 速度方向（vy / vx）用于判断弹回、侧向逃逸
        - 二阶差分加速度仅保留为诊断量，不作为主碰撞信号
    """
    result = KinematicsSequence()

    for i in range(len(track)):
        point = KinematicsPoint(
            pos=track[i].pos,
            time=track[i].time,
        )

        if i >= 1:
            point.vx = (track[i].x - track[i-1].x) / dt
            point.vy = (track[i].y - track[i-1].y) / dt
            point.speed = sqrt(point.vx**2 + point.vy**2)

        # 仅作为诊断量输出，不用于主碰撞判定
        if i >= 2:
            prev_vx = (track[i-1].x - track[i-2].x) / dt
            prev_vy = (track[i-1].y - track[i-2].y) / dt
            point.ax = (point.vx - prev_vx) / dt
            point.ay = (point.vy - prev_vy) / dt
            point.acceleration = sqrt(point.ax**2 + point.ay**2)

        result.append(point)

    return result
```

### 4.4 碰撞/弹回检测（抛物线拟合残差 + 方向变化）

基于连续帧的**局部抛物线拟合残差**与**速度方向变化**检测碰撞事件：

```python
def detect_collision_events(track: List[TrackPoint],
                            hoop_region: Rect,
                            backboard_region: Optional[Rect],
                            sigma_pos: float,
                            baseline_window: int = 5) -> List[CollisionEvent]:
    """
    检测球轨迹中的碰撞/弹回候选事件。

    主信号:
    1. 抛物线拟合残差：球偏离自由飞行模型的程度
    2. 速度方向变化：vy 翻转 / vx 剧烈反向变化

    判定原则:
    - 大残差 + 向上翻转/侧向逃逸 => 强不进球证据
    - 大残差但最终仍向下 => 可能擦筐或打板进球，继续看序列
    - 无大残差 => 不能证明没有碰撞，只能说明"未观察到显著打铁信号"
    """
    events = []
    segments = split_into_continuous_segments(track, max_gap_frames=1)

    for seg in segments:
        if len(seg) < baseline_window:
            continue

        fitted = fit_parabola(seg)  # x(t), y(t) 或仅 y(t)~t² 的局部模型
        residuals = compute_pointwise_residuals(seg, fitted)

        for i in range(1, len(seg) - 1):
            residual_px = residuals[i]
            residual_sigma = residual_px / max(sigma_pos, 1e-6)

            prev_pt = seg[i - 1]
            curr_pt = seg[i]
            next_pt = seg[i + 1]

            vy_reversed = (
                prev_pt.vy is not None and next_pt.vy is not None and
                prev_pt.vy > 0 and next_pt.vy < 0
            )
            vx_reversed = (
                prev_pt.vx is not None and next_pt.vx is not None and
                abs(prev_pt.vx) > 1e-3 and abs(next_pt.vx) > 1e-3 and
                prev_pt.vx * next_pt.vx < 0
            )
            lateral_escape = abs(next_pt.vx or 0) > abs(next_pt.vy or 0) * 1.2

            # 运行时阈值应使用“σ阈值 + 像素下限”的组合，而不是加速度/g 比值
            if residual_sigma >= 3.0 or (residual_sigma >= 2.0 and is_consistent_multi_frame(residuals, i)):
                events.append(CollisionEvent(
                    frame_idx=curr_pt.frame_idx,
                    time=curr_pt.time,
                    residual_px=residual_px,
                    residual_sigma=residual_sigma,
                    in_hoop_region=point_in_rect(curr_pt.pos, hoop_region),
                    in_backboard_region=(point_in_rect(curr_pt.pos, backboard_region)
                                         if backboard_region else False),
                    vy_reversed=vy_reversed,
                    vx_reversed=vx_reversed,
                    lateral_escape=lateral_escape,
                ))

    return events
```

### 4.5 连续帧进球判定算法

```python
def judge_goal_by_continuity(track: List[TrackPoint],
                             kinematics: KinematicsSequence,
                             collisions: List[CollisionEvent],
                             hoop: HoopInfo,
                             frame_info: FrameInfo,
                             backboard_region: Optional[Rect] = None) -> GoalJudgment:
    """
    基于连续帧的运动学分析判断是否进球。

    判定逻辑（从第一性原理推导）：
    1. 球必须接近并穿越篮筐平面
    2. 球在穿越前后的局部时间窗内应保持总体向下
    3. 显著大残差的角色是“排除打铁”，不是“穷举分类所有碰撞”
    4. 对打板进球需分析碰撞序列，而不能只看最后一次碰撞
    5. 证据不足时退化到反证法
    """

    hoop_y = hoop.center_y
    hoop_left = hoop.left
    hoop_right = hoop.right

    # ---- Step 1: 找到球接近篮筐平面的帧段 ----
    approach_frames = find_approach_segment(kinematics, hoop_y,
                                            tolerance=hoop.height * 1.5)
    if not approach_frames:
        return GoalJudgment(is_goal=False, reason="球未接近篮筐区域")

    # ---- Step 2: 分析接近段的运动方向 ----
    downward_frames = sum(1 for f in approach_frames if f.vy is not None and f.vy > 0)
    if downward_frames == 0:
        return GoalJudgment(is_goal=False, reason="球在篮筐区域未呈现向下运动")

    # ---- Step 3: 检查穿越篮筐平面 ----
    crossing = detect_plane_crossing(kinematics, hoop_y, hoop_left, hoop_right)
    if not crossing:
        return GoalJudgment(is_goal=False, reason="球未穿越篮筐平面")

    # ---- Step 4: 分析碰撞序列 ----
    board_hits = [c for c in collisions if c.in_backboard_region]
    rim_hits = [c for c in collisions if c.in_hoop_region and not c.in_backboard_region]

    strong_reject = any(
        c.in_hoop_region and (c.vy_reversed or c.lateral_escape or c.vx_reversed)
        for c in collisions
    )
    if strong_reject:
        return GoalJudgment(
            is_goal=False,
            reason="检测到显著弹回/侧向逃逸证据，判为不进球",
        )

    if board_hits:
        # 打板候选：允许先碰板、后恢复向下并完成穿越
        post_crossing = get_post_window(kinematics, crossing.time, window_s=0.3)
        still_downward = any(p.vy is not None and p.vy > 0 for p in post_crossing)
        if still_downward:
            return GoalJudgment(
                is_goal=True,
                goal_type="bankshot",
                confidence=0.82,
                reason="碰板后恢复向下并完成穿越，符合打板进球序列",
                crossing_time=crossing.time
            )

    if len(rim_hits) == 0 and len(board_hits) == 0:
        return GoalJudgment(
            is_goal=True,
            goal_type="swish_or_clean",
            confidence=0.95,
            reason="未观察到显著打铁证据，球平滑穿越篮筐平面",
            crossing_time=crossing.time
        )

    post_crossing = get_post_window(kinematics, crossing.time, window_s=0.3)
    still_downward = any(p.vy is not None and p.vy > 0 for p in post_crossing)
    if still_downward:
        return GoalJudgment(
            is_goal=True,
            goal_type="rim_in",
            confidence=0.80,
            reason="存在接触/微扰，但穿越后仍保持向下运动",
            crossing_time=crossing.time
        )

    # ---- Step 5: 反证法兜底 ----
    no_bounce = channel_8_no_bounce_evidence(
        kinematics=kinematics,
        hoop=hoop,
        frame_info=frame_info,
        window_s=1.0,
    )
    if no_bounce is not None:
        return GoalJudgment(
            is_goal=True,
            goal_type="inferred",
            confidence=no_bounce["confidence"],
            reason=no_bounce["detail"],
            crossing_time=crossing.time
        )

    return GoalJudgment(is_goal=False, reason="证据不足")
```

### 4.6 球"消失-重现"分析

当球在篮筐区域被遮挡时，分析消失和重现的模式：

```python
def analyze_disappear_reappear(track: List[TrackPoint],
                                hoop: HoopInfo) -> DisappearPattern:
    """
    分析球在篮筐区域的"消失-重现"模式。
    
    人类判断进球的关键直觉之一：
    - 进球时：球平滑消失在篮筐区域，从篮筐正下方以低速垂直落出
    - 不进球时：球消失后很快从侧面/上方以高速弹出
    
    关键指标：
    1. 消失时的角度和速度 → 是否"合理地指向篮筐内部"
    2. 消失到重现的时间间隔 → 是否符合穿网时间与检测延迟共同决定的工程窗口（0.06~1.0s）
    3. 重现的位置 → 在篮筐正下方 vs 侧面
    4. 重现的速度和方向 → 缓慢向下 vs 快速弹射
    """
    
    # 找到消失帧（追踪中断起点）
    gaps = find_tracking_gaps(track, min_gap_frames=2)
    
    for gap in gaps:
        last_visible = track[gap.start_idx]
        first_reappear = track[gap.end_idx] if gap.end_idx < len(track) else None
        
        # ---- 消失分析 ----
        disappear_in_hoop_region = point_near_hoop(last_visible.pos, hoop)
        disappear_angle = atan2(last_visible.vy, last_visible.vx) if last_visible.vy else None
        disappear_speed = last_visible.speed
        
        # ---- 重现分析 ----
        if first_reappear:
            time_gap = first_reappear.time - last_visible.time
            reappear_below_hoop = first_reappear.y > hoop.bottom
            reappear_near_center = abs(first_reappear.x - hoop.center_x) < hoop.width * 0.6
            reappear_speed = first_reappear.speed
            reappear_downward = first_reappear.vy > 0 if first_reappear.vy else False
            
            # ---- 模式匹配 ----
            
            # 进球模式：消失在篮筐区域，0.06~1.0s后从正下方缓慢出现
            # v1.5 修正：下界从 0.2s 降至 0.06s（覆盖三分空心最快穿筐 56ms）
            #           上界从 0.8s 升至 1.0s（覆盖卡筐/多次弹跳后进球极端场景）
            if (disappear_in_hoop_region and
                0.06 <= time_gap <= 1.0 and
                reappear_below_hoop and
                reappear_near_center and
                reappear_downward):
                return DisappearPattern(
                    pattern="goal",
                    confidence=0.75,
                    detail=f"消失在篮筐区域，{time_gap:.2f}s后从正下方垂直落出"
                )
            
            # 打铁模式：消失后快速弹出
            if (disappear_in_hoop_region and
                time_gap < 0.15 and
                not reappear_downward and
                reappear_speed > disappear_speed * 0.5):
                return DisappearPattern(
                    pattern="bounce_out",
                    confidence=0.80,
                    detail=f"快速弹出（{time_gap:.2f}s），速度方向反转"
                )
    
    return DisappearPattern(pattern="unknown", confidence=0.0)
```

## 五、全帧扫描架构与现有通道的集成

### 5.1 改造目标

当前系统的两阶段采样已实现"粗扫+精扫"框架（`detect.py` 中 `two_stage` 参数），但精扫阶段仍有跳帧可能。改造目标：

> **精扫阶段必须 `frame_step=1`（逐帧），在候选区间内对原始视频的每一帧进行运动学分析。**

### 5.2 全帧精扫流水线

```
原始视频（30fps）
    │
    ├─── 阶段1: 粗扫（3fps 采样）
    │    ├─ YOLO 检测球体/篮筐（通道 1a/1b）
    │    ├─ 帧差分运动突变（通道 3）
    │    ├─ 音频事件检测（通道 5）
    │    └─ 篮网光流检测（通道 4）
    │    → 输出候选时间窗口列表
    │
    ├─── 阶段2: 全帧精扫（候选窗口内 30fps 逐帧）
    │    ├─ 逐帧 YOLO 检测 → 建立连续轨迹
    │    ├─ 逐帧运动学计算（位置/速度/诊断加速度）
    │    ├─ 碰撞/弹回检测（拟合残差 + 方向变化）
    │    ├─ 连续性进球判定（本文核心算法）
    │    ├─ 球"消失-重现"分析
    │    └─ 篮网逐帧光流分析（方向纯净度）
    │    → 输出精确进球判定
    │
    └─── 阶段3: 多通道融合 + 因果验证
         ├─ 跨通道互证（现有逻辑）
         ├─ 因果推理链验证（算法E，现有）
         ├─ 事件合并 + 冷静期过滤
         └─ 最终输出
```

### 5.3 与现有通道的关系

| 现有通道 | 本文算法增强 | 改造范围 |
|---------|------------|---------|
| **通道 1a**（几何穿越） | 新增运动学连续性分析：抛物线拟合残差、方向变化检测、碰撞序列模式匹配 | `detect.py` 中 `judge_goal_by_trajectory()` 增强 |
| **通道 1b**（启发式） | 新增"消失-重现"模式分析：消失角度、重现位置、时间间隔 | `detect.py` 中 `fallback_heuristic_v2()` 增强 |
| **通道 4**（有向光流） | 逐帧光流分析（现已实现方向纯净度），与运动学数据交叉验证 | `net_deform.py` 已支持，无需改动 |
| **因果推理链**（算法E） | 为运动学判定提供上下文验证 | `causal_chain.py` 已实现 |
| **新增** | 反证法通道：在球被遮挡时，通过"未观察到弹回"间接推断进球 | 新增逻辑 |

### 5.4 反证法通道（新增通道 8）

基于第一性原理的关键洞察：

> **不要试图证明"球进了"，而是试图证明"球没有被弹回来"——这在信息不完整时，往往更容易做到。**

```python
def channel_8_no_bounce_evidence(kinematics: KinematicsSequence,
                                  hoop: HoopInfo,
                                  frame_info: FrameInfo,
                                  window_s: float = 1.5) -> Optional[Dict]:
    """
    反证法通道：检查球到达篮筐区域后，是否存在弹回证据。

    逻辑：
    1. 球必须先到达篮筐中心附近，且运动方向指向篮筐（排除 Air Ball / 路过球）
    2. 在随后 window_s 秒内，搜索弹回信号：
       - 速度方向反转（vy < -threshold）
       - 从篮筐上方或侧方重现
       - 明显侧向逃逸
    3. 若未找到弹回信号，再检查观察覆盖率是否足够
    4. 仅在覆盖率达标时，输出低上限的间接支持证据

    注意：返回的 confidence 是未校准证据分，不等同于真实概率。
    反证法的角色是“弱支持”，不能独立完成高置信度判定。
    """

    approach_time = find_last_approach_time(kinematics, hoop)
    if approach_time is None:
        return None

    approach_point = get_point_at_time(kinematics, approach_time)
    if approach_point is None:
        return None

    # ---- 前置条件 ----
    dist_to_hoop_center = distance(approach_point.pos, hoop.center)
    if dist_to_hoop_center > hoop.width * 0.8:
        return None  # Air Ball 嫌疑，不使用反证法

    if approach_point.vy is not None and approach_point.vy < 0:
        return None  # 球在向上运动，不可能是进球后的自然落下

    post_frames = [p for p in kinematics
                   if approach_time < p.time <= approach_time + window_s]
    if not post_frames:
        return None

    bounce_evidence = []
    for p in post_frames:
        if p.vy is not None and p.vy < -BOUNCE_SPEED_THRESHOLD:
            bounce_evidence.append(("velocity_reversal", p.time))

        if p.y < hoop.top:
            bounce_evidence.append(("upper_reappear", p.time))

        if getattr(p, "x_dist_from_hoop", None) is not None and p.x_dist_from_hoop > hoop.width * 0.5:
            bounce_evidence.append(("lateral_escape", p.time))

    if bounce_evidence:
        return None

    # ---- 覆盖率检查 ----
    viewport_coverage = compute_viewport_coverage(approach_time, window_s, frame_info)
    detection_coverage = compute_detection_coverage(frame_info, approach_time, window_s)
    combined_coverage = viewport_coverage * detection_coverage

    if combined_coverage < 0.5:
        return None

    base_confidence = 0.45 if combined_coverage >= 0.8 else 0.30
    return {
        "timestamp": approach_time,
        "confidence": base_confidence,
        "detail": f"反证法: 覆盖率 {combined_coverage:.0%} "
                  f"(视口 {viewport_coverage:.0%} × 检测 {detection_coverage:.0%}), "
                  f"{len(post_frames)} 帧已检查, 未观察到弹回",
        "channel": "8"
    }
```

> **工程约束**：通道 8 的证据分上限固定为 **0.45**。如果仅有反证法而没有穿越、篮网形变或上下文证据，不应直接输出“高置信进球”。

## 六、人类视觉推理的算法化

### 6.1 人类怎么判断进球？

通过内省分析，人类判断进球时使用以下推理通道（优先级从高到低）：

| 通道 | 人类直觉 | 算法化方法 | 当前实现状态 |
|------|---------|-----------|------------|
| **抛物线延伸** | 看到球出手，大脑"脑补"轨迹落点 | Kalman 滤波 + 抛物线预测 | ⬜ 算法B（T-1.9.16） |
| **消失方式** | 球以"对"的角度消失在篮筐区域 | 消失帧速度/角度分析 | ⬜ 本文 4.6 节 |
| **重现方式** | 球从正下方缓慢落出 vs 从侧面弹出 | 重现帧位置/速度/方向分析 | ⬜ 本文 4.6 节 |
| **时间间隔** | 消失后"恰当的"延迟后出现 | 消失-重现时间间隔匹配 | ⬜ 本文 4.6 节 |
| **篮网晃动** | 篮网鼓包→收缩→摆动 | 有向光流方向纯净度 | ✅ 通道4（T-1.9.13） |
| **球员反应** | 投篮者跟投/庆祝、其他人回防 | 庆祝动作检测 + 因果推理链 | ✅ 通道7 + 算法E |
| **无弹回** | "没看到球弹回来" | 反证法通道 | ⬜ 本文 4.5/5.4 节 |

### 6.2 为什么人能在篮网被挡住时判断进球？

关键洞察：

> **人判断的从来就不是"篮网是否鼓包"，而是"球的整个生命周期是否讲了一个'进球的故事'"。**

人使用的是**整条因果链的多个环节**做交叉验证：

```
[阶段1: 起飞]     [阶段2: 飞行]     [阶段3: 消失]     [阶段4: 重现]     [阶段5: 后果]
                                          ↑
球出手 →          抛物线弧度合理 →    球以正确角度     球从篮筐下方      球员转身回防
速度/角度            方向指向篮筐       进入篮筐区域     缓慢垂直落下      无人抢篮板
                                     没有速度突变      速度被衰减
```

**你不需要看到每一个阶段，只要看到其中几个阶段的特征一致，就能高置信度地判断。**

这正是现有**因果推理链验证器（算法E）** 所实现的——检查候选事件前后的因果信号是否存在。本文的贡献是将这个思想扩展到了**帧级别的连续性分析**。

## 八、理论分析与预期效果

### 8.1 为什么全帧扫描是必须的

| 物理量 | 需要的最小帧率 | 原因 |
|--------|--------------|------|
| 球位置追踪 | ≥ 15fps | 球速 ~8m/s，每帧移动约 0.5m |
| 速度计算 | ≥ 15fps | 需要至少相邻2帧的位置差 |
| 加速度计算 | ≥ 15fps | 需要至少相邻3帧的速度差 |
| 碰撞检测 | ≥ 24fps | 碰撞持续 ~1-2 帧，低帧率会错过 |
| 穿越检测 | ≥ 10fps | 穿越时间 0.05~0.4s，10fps 保证至少 0.5~4 帧 |

结论：候选区间内的精扫**必须使用原始帧率**（通常 30fps），3fps 的采样完全不足以支撑运动学分析。

### 8.2 预期效果

## 九、核心理论验证

> 验证代码：`ai-engine/tests/test_kinematics_theory.py`
>

>
> 已完成 5 个核心命题的首轮数值验证；其中命题 3 的二阶差分结果仅保留为**理论对照**，工程实现以后续残差验证为准 ✅

### 9.1 命题 1 验证：球穿越篮筐平面时间

**命题**：球穿越篮筐平面的物理时间约 0.1~0.3 秒。

**验证方法**：根据抛物线运动方程，计算不同投篮类型到达篮筐时的垂直速度，再用 `穿越时间 = 球直径 / 垂直速度` 求解。

| 投篮类型 | 出手速度 | 出手角度 | 入筐垂直速度 | 纯穿筐时间 |
|---------|---------|---------|------------|----------|
| 罚球 | 7.2 m/s | 52° | 3.60 m/s | 67 ms |
| 三分球 | 9.5 m/s | 50° | 4.35 m/s | 56 ms |
| 上篮 | 4.5 m/s | 55° | 0.65 m/s | 376 ms |
| 扣篮 | — | — | ~3.0 m/s（估算） | 81 ms |

**结论**：

- ✅ 罚球、三分、扣篮的纯穿筐时间在 56~81ms，含穿网时间约 100~230ms
- ⚠️ 极端上篮场景（球近乎"放入"篮筐）穿筐时间可达 376ms，超出文档声明的 300ms 上限
- **修正**：文档取值从"0.1~0.3s"调整为"**0.05~0.4s**"以覆盖所有投篮类型；典型场景（罚球/三分/扣篮）仍在 0.05~0.25s 范围内

**参考文献**：
- Brancazio (1981) "Physics of basketball", *American Journal of Physics* — 投篮出手速度 6-8 m/s, 出手角度 45-55°
- Silverberg et al. (2003) "Optimal release conditions for the free throw" — 罚球出手速度 ~7.2 m/s, 出手角度 ~52°
- Tran & Silverberg (2008) "Optimal release conditions for the free throw in men's basketball", *J. Sports Sciences* — 最优入筐角度 ~46°

### 9.2 命题 2 验证：像素空间重力估算

**命题**：可以从篮筐的像素宽度反推像素空间的重力加速度。

**公式推导**：

```
已知: 篮筐物理直径 = 0.4572m, 画面中篮筐占 W_px 像素, 视频帧率 fps
=> pixel_per_meter = W_px / 0.4572
=> g_pixel = 9.81 × pixel_per_meter / fps²  (单位: px/frame²)
```

**验证结果**：

| 拍摄场景 | 篮筐像素宽 | pixel/meter | g_pixel (px/frame²) | 1帧落体距离 |
|---------|-----------|-------------|--------------------|-----------| 
| 近景 1080p (15%) | 288 px | 629.9 | 6.87 | 3.4 px |
| 中景 1080p (7%) | 134 px | 293.1 | 3.19 | 1.6 px |
| 远景 1080p (3%) | 58 px | 126.9 | 1.38 | 0.7 px |
| 近景 720p (15%) | 192 px | 419.9 | 4.58 | 2.3 px |
| 手机竖拍 (12%) | 130 px | 284.3 | 3.10 | 1.5 px |

**关键发现 — KalmanTracker 硬编码值的问题**：

```
中景 1080p@3fps 计算得 g_pixel = 319.47 px/frame²
KalmanTracker 硬编码: gravity_scale = 2.0 px/frame²
偏差: 15,873%
```

> ⚠️ **G-1 差距确认**：现有 `KalmanTracker` 的 `gravity_scale=2.0` 仅是粗略近似值，与物理正确值偏差巨大。建议替换为 `estimate_gravity_pixel()` 动态计算。

**理论基础**：Hartley & Zisserman (2004) *"Multiple View Geometry in Computer Vision"* Ch.6 — 已知物体尺寸的单目尺度推断

**局限性**：
- 假设篮筐近似面向相机（无严重透视变形）
- 假设球和篮筐在近似同一深度平面

### 9.3 命题 3 验证：理想无噪声条件下的碰撞偏离量级（理论对照）

**命题**：在理想无噪声条件下，打铁弹出相对自由飞行会产生远大于重力基线的运动偏离。

**验证方法**：模拟三种轨迹（抛物线/碰撞反弹/擦筐进球），用二阶差分计算加速度，作为**无噪声理论对照量**，用于说明碰撞信号与自由飞行之间存在显著量级差，而**不是**直接作为工程实现的碰撞检测器。

| 轨迹类型 | 平均加速度 (px/f²) | 最大加速度 (px/f²) | 最大/g 比值 | 判定 |
|---------|-------------------|-------------------|-----------|-----|
| 空心球 (Swish) | 3.195 | 3.195 | **1.00x** | 无碰撞 ✅ |
| 擦筐进球 | 3.447 | 6.311 | **1.98x** | 轻微碰撞 |
| 打铁弹出 | 6.615 | 47.502 | **14.87x** | 剧烈碰撞 ❌ |

**结论**：

- ✅ 该实验说明：**碰撞确实会带来明显高于自由飞行基线的运动偏离**，因此“用轨迹偏离检测碰撞”在物理上是成立的
- ⚠️ 这里的 **3.0x** 仅是**无噪声理想条件**下的量级参考，**不能**直接作为工程阈值
- 工程实现应改用**抛物线拟合残差 / σ_pos** 阈值，而不是 `加速度 / g_pixel`
- 擦筐进球是否成立，仍需结合**最终是否继续向下穿越**、消失-重现模式和反证法综合判断

**参考文献**：
- Knudson (1993) "Biomechanics of the basketball jump shot" — 碰篮筐反弹系数 0.5-0.8
- Okubo & Hubbard (2006) "Dynamics of the basketball shot", *J. Sports Sciences* — 碰撞持续时间 ~10-20ms, 峰值力 ~100-300N

### 9.4 命题 4 验证：YOLO bbox 噪声对加速度的影响

**命题**：YOLO bbox 中心坐标噪声经二阶差分后被严重放大，必须平滑处理。

**理论噪声传播公式**：

```
σ_vel = √2 · σ_pos / dt        (一阶差分放大)
σ_acc = √6 · σ_pos / dt²       (二阶差分放大)
```

**噪声放大量化（30fps, 中景 1080p）**：

| σ_pos (px) | σ_acc (px/s²) | g_pixel (px/s²) | SNR (g/σ_acc) | 可用性 |
|-----------|--------------|----------------|---------------|-------|
| 2.0 | 4,409 | 2,875 | 0.65 | ❌ 不可用 |
| 3.0 | 6,614 | 2,875 | 0.43 | ❌ 不可用 |
| 5.0 | 11,023 | 2,875 | 0.26 | ❌ 不可用 |
| 8.0 | 17,636 | 2,875 | 0.16 | ❌ 不可用 |

**Savitzky-Golay 滤波改善**（窗口=5）：

| σ_pos (px) | 原始 SNR | SG 滤波后 SNR | 可用性 |
|-----------|---------|--------------|-------|
| 2.0 | 0.65 | 1.46 | ⚠️ 仍不足 |
| 3.0 | 0.43 | 0.97 | ⚠️ 仍不足 |
| 5.0 | 0.26 | 0.58 | ⚠️ 仍不足 |
| 8.0 | 0.16 | 0.36 | ⚠️ 仍不足 |

**Monte Carlo 模拟验证**（200 次试验，碰撞阈值 = 3.0x 重力）：

| 条件 | σ_pos=3px 假碰撞率 | σ_pos=5px 假碰撞率 |
|------|-------------------|-------------------|
| 无滤波 | **100%** | **100%** |
| + Kalman 滤波 | **97%** | **100%** |

> ⚠️ **G-2 差距确认（关键发现）**：YOLO bbox 噪声使得**直接对检测位置做二阶差分计算加速度完全不可行**。即便使用 Kalman 滤波平滑位置，假碰撞率仍高达 97%~100%。
>
> **结论与建议**：
> 1. 碰撞检测**不能单独依赖**二阶差分加速度突变
> 2. 必须结合**多帧一致性分析**（连续多帧加速度异常才视为碰撞）
> 3. 必须结合**多通道证据融合**（加速度突变 + 速度方向变化 + 位置偏移）
> 4. 考虑使用**抛物线拟合残差**替代二阶差分（对噪声更鲁棒）
> 5. Kalman 滤波器的过程噪声参数需要仔细调优

**参考文献**：
- Press et al. (2007) *"Numerical Recipes"* Ch.5.7 — 数值微分中的噪声误差放大
- Savitzky & Golay (1964) "Smoothing and Differentiation of Data by Simplified Least Squares Procedures", *Analytical Chemistry*

### 9.5 命题 5 验证：消失-重现时间间隔

**命题**：进球时球从消失到重现的时间间隔通常落在 **0.06~1.0s**；其中纯穿筐最快场景接近 56~83ms，极端卡筐/多次弹跳后进球可延长到约 0.6s 以上。

**验证方法**：计算不同入筐速度下球穿过篮网（40cm）的时间，考虑有无网阻力。

| 投篮类型 | 入筐速度 (m/s) | 无阻力穿网 (ms) | 有网阻穿网 (ms) |
|---------|--------------|----------------|----------------|
| 罚球 | 3.5 | 100 | 130~180 |
| 中投 | 4.0 | 90 | 117~162 |
| 三分 | 5.0 | 75 | 97~134 |
| 上篮 | 2.0 | 147 | 191~265 |
| 扣篮 | 3.0 | 113 | 146~203 |

**视觉遮挡总时间**（含篮筐结构 + 篮网）：

- 最快场景（三分空心球）：**83ms** 穿过遮挡区
- 最慢场景（擦筐/卡筐进球）：**~583ms**

**结论**：

- ✅ 理论消失-重现时间范围约为 **83~583ms**
- ✅ 若考虑检测丢失确认与重检测延迟，工程可用窗口应放宽为 **0.06~1.0s**，而不是旧版的 **0.2~0.8s**
- ⚠️ 下界放宽后会引入更多快速弹出假阳性风险，因此必须与 `reappear_below_hoop`、`reappear_near_center`、`reappear_downward` 联合使用
- 快速弹出（打铁）重现时间通常 **< 0.15s**，可作为排除信号之一，但不能单独作为进/不进判据

### 9.6 采样率必要性验证

**不同帧率下球穿越事件的帧数**：

| 投篮场景 | 穿越时间 | 3fps | 5fps | 10fps | 15fps | 24fps | 30fps |
|---------|---------|------|------|-------|-------|-------|-------|
| 三分空心 | 56ms | 0.2 ❌ | 0.3 ❌ | 0.6 ❌ | 0.9 ❌ | 1.4 | 1.8 |
| 罚球空心 | 67ms | 0.2 ❌ | 0.4 ❌ | 0.8 ❌ | 1.2 | 1.9 | 2.4 |
| 上篮进球 | 376ms | 0.4 ❌ | 0.6 ❌ | 1.2 | 1.8 | 2.9 | 3.6 |
| 扣篮 | 81ms | 0.2 ❌ | 0.4 ❌ | 0.8 ❌ | 1.2 | 1.9 | 2.4 |

> ❌ = 穿越事件不到 1 帧，极大概率被完全跳过

**结论**：

- **3fps**：所有场景穿越均 < 1 帧，运动学分析**完全不可行**
- **10fps**：仅上篮勉强可用，三分和扣篮仍不足
- **24fps+**：加速度计算需要至少 3 帧，**24fps 是运动学分析的最低要求**
- **30fps**（推荐）：所有场景穿越至少 1.8~3.6 帧，运动学分析可行

### 9.7 像素空间重力估算实现方案

基于命题 2 的验证结果，提出替换 `KalmanTracker` 硬编码 `gravity_scale=2.0` 的方案：

```python
def estimate_gravity_pixel(hoop_w_pixels: int, fps: int) -> float:
    """
    从篮筐像素宽度动态估算像素空间重力加速度。
    
    替代 KalmanTracker 中硬编码的 gravity_scale=2.0。
    
    参数:
        hoop_w_pixels: 检测到的篮筐像素宽度
        fps: 视频帧率
    
    返回:
        g_pixel: 重力加速度 (px/frame²)
    
    推导:
        physical_hoop_diameter = 0.4572 m  (NBA/FIBA 标准)
        pixel_per_meter = hoop_w_pixels / 0.4572
        g_pixel = 9.81 * pixel_per_meter / fps²
    
    示例:
        中景 1080p, 篮筐 134px, 30fps → g = 3.19 px/frame²
        中景 1080p, 篮筐 134px, 3fps  → g = 319.5 px/frame²
    """
    HOOP_DIAMETER_M = 0.4572
    pixel_per_meter = hoop_w_pixels / HOOP_DIAMETER_M
    return 9.81 * pixel_per_meter / (fps ** 2)
```

## 十、已知问题与改进方向

### 10.1 G-1：重力参数校准

| 项目 | 说明 |
|------|------|
| 问题 | `KalmanTracker` 硬编码 `gravity_scale=2.0`，与物理值偏差达 15,873% |
| 原因 | 该值未基于场景参数动态计算 |
| 解决方案 | 使用 `estimate_gravity_pixel(hoop_w_pixels, fps)` 动态计算（见 9.7 节） |
| 优先级 | P1 |
| 影响范围 | `ai-engine/tracker.py` KalmanTracker 状态转移矩阵 |

### 10.2 G-2：YOLO 噪声抑制

| 项目 | 说明 |
|------|------|
| 问题 | YOLO bbox 噪声经二阶差分后 SNR < 1.0，原始加速度计算完全不可用 |
| 原因 | 二阶差分将 σ_pos 放大为 `√6·σ_pos/dt²`，在 30fps 下放大约 2,200 倍 |
| 解决方案 | (1) 多帧一致性分析 (2) 抛物线拟合残差 (3) 多通道证据融合 |
| 优先级 | P0（阻塞碰撞检测的实际部署） |
| 影响范围 | `ai-engine/kinematics.py`（新增）、碰撞检测算法全局 |

**G-2 备选方案比较**：

| 方案 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| S-G 滤波 + 二阶差分 | 多项式拟合平滑后求导 | 保形性好 | SNR 改善有限（√5 ≈ 2.24x） |
| Kalman 滤波 + 二阶差分 | 状态估计后求导 | 自适应 | 实测假碰撞率仍 97%+ |
| **抛物线拟合残差** | 拟合自由抛物线，大残差 = 碰撞 | 对噪声鲁棒 | 需要足够帧数（≥5帧） |
| **多帧一致性检测** | 连续 N 帧加速度异常才触发 | 降低假阳性 | 可能漏检瞬时碰撞 |
| **速度方向变化检测** | 检测 vy 符号翻转 | 不受噪声放大影响 | 只能检测弹回型碰撞 |

> **推荐方案**：组合使用"**抛物线拟合残差**"+ "**速度方向变化检测**"，避免直接使用对噪声极度敏感的二阶差分。

### 10.3 命题 1 参数修正

| 项目 | 说明 |
|------|------|
| 原文档 | 球穿越篮筐平面时间 0.1~0.3s |
| 验证结果 | 典型场景 56~81ms，极端上篮 376ms |
| 修正 | 扩展为 **0.05~0.4s**，并注明典型场景在 0.05~0.25s |

## 十一、视频清晰度与参数自适应

> 验证代码：`ai-engine/tests/test_kinematics_theory.py` — `test_resolution_fps_parameter_adaptation()`
>
> 核心函数：`compute_adaptive_params(img_w, img_h, native_fps, bitrate_kbps)`

### 11.1 问题背景

当前系统使用固定参数配置（`config.yaml` 中 `sample_fps: 6`, `yolo_confidence: 0.25`, YOLO `imgsz=640`），但实际输入视频的清晰度差异巨大：

- **4K 专业赛事直播** (3840×2160@60fps, 50Mbps)
- **手机 1080p 直拍** (1920×1080@30fps, 8Mbps)
- **微信/社交媒体转发** (1920×1080@30fps, 2Mbps — 二次压缩)
- **抖音/快手标清** (1280×720@30fps, 4Mbps)
- **低清监控** (854×480@15fps, 800kbps)
- **极低清旧视频** (640×360@15fps, 600kbps)

不同清晰度下，球体的像素尺寸、检测噪声、运动学分析可行性都有本质差异，**固定参数无法兼顾所有场景**。

### 11.2 目标检测能力分析

球体和篮筐在画面中的像素尺寸取决于**分辨率 × 拍摄距离**：

| 分辨率 | 近景 (15%) | 中景 (7%) | 远景 (3%) | 极远景 (1.5%) |
|-------|------------|-----------|-----------|--------------|
| **4K** (3840) | 球 306px ✅ | 球 143px ✅ | 球 61px ✅ | 球 31px ✅ |
| **1080p** (1920) | 球 153px ✅ | 球 71px ✅ | 球 31px ✅ | 球 15px ⚠️ |
| **720p** (1280) | 球 102px ✅ | 球 48px ✅ | 球 20px ✅ | 球 10px ❌ |
| **480p** (854) | 球 68px ✅ | 球 32px ✅ | 球 14px ⚠️ | 球 7px ❌ |
| **360p** (640) | 球 51px ✅ | 球 24px ✅ | 球 10px ❌ | 球 5px ❌ |

> ✅ = YOLO 可靠检测（球径 ≥ 20px）
> ⚠️ = 勉强可检测（12-20px）
> ❌ = 不可检测（< 12px）

**关键结论**：
- 720p 及以下分辨率的**极远景**（>25m）球体检测不可行
- 480p 的远景、360p 的远景已处于检测能力边缘
- **远景低分辨率场景应退化到篮网形变 + 启发式通道，不依赖球体追踪**

### 11.3 粗扫采样率策略

粗扫目标是**快速定位候选区间**，不需要运动学分析。关键约束：进球前后球在篮筐附近的滞留时间 ~1-3 秒，因此每秒 2-3 帧即可检测到球的出现。

| 视频规格 | 原始 fps | 推荐粗扫 fps | 理由 | 1min 帧数 |
|---------|---------|-------------|------|----------|
| 4K | 60 | **3** | 大图检测慢，极低采样降开销 | 180 |
| 1080p | 30 | **3** | 标准策略，计算量降 90% | 180 |
| 720p | 24-30 | **4** | 中等分辨率，稍高采样弥补目标较小 | 240 |
| 480p | 30 | **6** | 小图检测快，可承受更高采样 | 360 |
| 480p@15fps | 15 | **15**（不降采样） | 原始帧率已低，不再降采样 | 900 |
| 360p | 15 | **15**（不降采样） | 原始帧率已低 | 900 |

> ⚠️ 当前 `config.yaml` 固定 `sample_fps: 6`，对高清视频偏高（浪费计算），对低帧率视频偏低（漏检）。

### 11.4 精扫帧率策略

精扫阶段做逐帧运动学分析，**必须使用原始帧率**（这是物理硬约束）：

| 原始 fps | 三分穿越帧数 (56ms) | 上篮穿越帧数 (376ms) | 运动学可行性 |
|---------|-------------------|-------------------|------------|
| **60** | 3.4 帧 | 22.6 帧 | ✅ 完全可行 |
| **30** | 1.7 帧 | 11.3 帧 | ✅ 完全可行 |
| **24** | 1.3 帧 | 9.0 帧 | ⚠️ 部分可行（三分穿越勉强） |
| **15** | 0.8 帧 | 5.6 帧 | ⚠️ 仅上篮/扣篮可分析 |

**结论**：
- **30fps+**：所有投篮类型的运动学分析均可行
- **24fps**：大部分场景可行，最快穿越（三分空心）接近极限
- **15fps**：仅上篮/扣篮穿越有足够帧数，三分/罚球运动学分析不可行
- **15fps 以下**：运动学分析**完全不可行**，必须退化为篮网形变 + 启发式

### 11.5 YOLO 输入尺寸 (imgsz) 自适应

YOLO 将输入图像缩放到 `imgsz × imgsz` 进行检测。当前固定 `imgsz=640`，但：

- **4K (3840px)**：缩放比 640/3840 = 0.17，远景球 61px → 仅 10px，仍可检测
- **1080p (1920px)**：缩放比 640/1920 = 0.33，远景球 31px → 10px，边缘可检测
- **480p (854px)**：缩放比 640/854 = 0.75，远景球 14px → 10px，勉强
- **360p (640px)**：缩放比 640/640 = 1.0，无缩放

**推荐策略**：

```
imgsz 选择逻辑:
1. 计算远景(3%)下球在缩放后的像素尺寸
2. 确保缩放后球径 ≥ 12px
3. imgsz 不低于 480 (YOLO 小目标检测下限)
4. imgsz 不超过原始宽度 (放大不增加信息量)
5. 4K 视频用 640 即可 (远景球缩放后仍 >10px)

结果:
  4K    → 640
  1080p → 768 (远景需要更大输入)
  720p  → 768
  480p  → 768 (接近原始宽度)
  360p  → 640 (等于原始宽度)
```

### 11.6 码率与压缩伪影的影响

同分辨率下，码率差异巨大影响检测质量。使用 **bpp**（bits per pixel per frame）量化：

```
bpp = 码率(bps) / (宽 × 高 × fps)
```

| bpp 范围 | 视觉质量 | 对检测的影响 | 参数调整建议 |
|---------|---------|------------|------------|
| > 0.1 | ★★★★★ 高清 | 无影响 | 标准参数 |
| 0.05~0.1 | ★★★★ 良好 | 基本无影响 | 标准参数 |
| 0.03~0.05 | ★★★ 中等 | 球体边缘模糊，conf 下降 | `yolo_conf` 降至 0.20 |
| 0.015~0.03 | ★★ 较差 | 块效应明显，bbox 噪声 ↑50% | `yolo_conf: 0.18`, `measurement_noise` ↑, `residual_sigma_single: 3.5`, `residual_sigma_double: 2.5` |
| < 0.015 | ★ 极差 | 严重伪影，检测不可靠 | `yolo_conf: 0.15`, 启用 VLM 补充 |

**典型场景 bpp**：

| 场景 | 分辨率 | 码率 | bpp | 质量 |
|------|-------|------|-----|------|
| 手机直拍 | 1080p@30 | 8 Mbps | 0.129 | ★★★★★ |
| 社交媒体标准 | 1080p@30 | 4 Mbps | 0.064 | ★★★★ |
| 微信压缩 | 1080p@30 | 2 Mbps | 0.032 | ★★★ |
| 二次转码 | 1080p@30 | 1 Mbps | 0.016 | ★★ |

### 11.7 KalmanTracker 参数自适应

所有 KalmanTracker 参数均可从 `(分辨率, 篮筐像素宽, fps, 码率)` 推算：

| 参数 | 计算方式 | 说明 |
|------|---------|------|
| `gravity_scale` | `9.81 × (hoop_w_px / 0.4572) / fps²` | 见 9.2 节，替代硬编码 2.0 |
| `process_noise` | `gravity_scale × 0.5` | 非重力外力的噪声建模 |
| `measurement_noise` | `max(1.5, ball_d_px × noise_factor)` | noise_factor: 高码率 0.08, 低码率 0.15 |
| `distance_threshold` | `max(30, ball_d_px × 2.5)` | 匹配距离随目标大小缩放 |
| `max_lost` | `max(3, int(0.8 × coarse_fps))` | 消失容忍帧数随采样率缩放 |

### 11.8 残差阈值自适应

运行时主碰撞指标应为**拟合残差 / 位置噪声基线**，而不是 `加速度 / 重力比`。因此自适应调参应围绕 `σ_pos` 和球径进行：

| 条件 | 单帧阈值 | 双帧阈值 | 理由 |
|------|---------|---------|------|
| 高清 + 近/中景 (bpp > 0.05, 球径 > 25px) | **3.0σ** | **2.0σ** | 噪声低，可用标准阈值 |
| 中等质量或小目标 (bpp 0.02-0.05 或球径 15-25px) | **3.5σ** | **2.5σ** | 噪声增大，提高阈值减少误报 |
| 低清或极小目标 (bpp < 0.02 或球径 < 15px) | **4.0σ** | **3.0σ** | 噪声极大，需更保守 |

> **工程建议**：最终阈值应使用 `max(k × σ_pos, residual_floor_px_ratio × ball_d_px)`，防止 `σ_pos` 被短时间窗口低估。

### 11.10 自适应参数计算函数

```python
def compute_adaptive_params(img_w: int, img_h: int,
                             native_fps: int, bitrate_kbps: int,
                             hoop_ratio: float = 0.07) -> dict:
    """
    根据视频规格自动计算最优检测参数。

    说明：
    - coarse_fps 用于粗扫
    - fine_fps 用于精扫/跟踪/残差分析，默认取 min(native_fps, 30)
    - gravity_pixel 必须按 fine_fps 计算，而不是按 coarse_fps 计算
    """
    HOOP_DIAMETER_M = 0.4572
    BALL_DIAMETER_M = 0.2426

    hoop_w_px = img_w * hoop_ratio
    ball_d_px = hoop_w_px * (BALL_DIAMETER_M / HOOP_DIAMETER_M)
    bpp = (bitrate_kbps * 1000) / (img_w * img_h * native_fps)

    # 粗扫 fps
    if native_fps <= 15:
        coarse_fps = native_fps
    elif img_w >= 3840:
        coarse_fps = 3
    elif img_w >= 1920:
        coarse_fps = 3
    elif img_w >= 1280:
        coarse_fps = 4
    else:
        coarse_fps = 6

    fine_fps = min(native_fps, 30) if native_fps > 24 else native_fps

    # YOLO imgsz (考虑远景 3% 场景)
    ball_d_far = img_w * 0.03 * (BALL_DIAMETER_M / HOOP_DIAMETER_M)
    min_imgsz = ceil(12 / ball_d_far * img_w / 32) * 32 if ball_d_far > 0 else 640
    imgsz = min(1280, max(480, min_imgsz))
    imgsz = min(imgsz, ceil(img_w / 32) * 32)
    if img_w >= 3840 and ball_d_far * (640 / img_w) >= 10:
        imgsz = 640

    # 重力参数：供精扫阶段的 Kalman / 预测使用，因此按 fine_fps 计算
    g_pixel = 9.81 * (hoop_w_px / HOOP_DIAMETER_M) / (fine_fps ** 2)

    # 噪声参数
    noise_factor = 0.08 if bpp > 0.05 else (0.12 if bpp > 0.02 else 0.15)
    measurement_noise = max(1.5, ball_d_px * noise_factor)

    # 残差阈值
    if bpp < 0.02 or ball_d_px < 15:
        residual_sigma_single = 4.0
        residual_sigma_double = 3.0
    elif bpp < 0.05 or ball_d_px < 25:
        residual_sigma_single = 3.5
        residual_sigma_double = 2.5
    else:
        residual_sigma_single = 3.0
        residual_sigma_double = 2.0

    return {
        'coarse_fps': coarse_fps,
        'fine_fps': fine_fps,
        'imgsz': imgsz,
        'yolo_confidence': 0.15 if bpp < 0.015 else (0.18 if bpp < 0.03 else 0.25),
        'gravity_pixel': round(g_pixel, 3),
        'tracker': 'kalman' if ball_d_px >= 20 and fine_fps >= 24 else 'iou',
        'process_noise': round(g_pixel * 0.5, 2),
        'measurement_noise': round(measurement_noise, 1),
        'distance_threshold': round(max(30, ball_d_px * 2.5), 0),
        'max_lost': max(3, int(0.8 * coarse_fps)),
        'residual_sigma_single': residual_sigma_single,
        'residual_sigma_double': residual_sigma_double,
        'residual_floor_px': round(ball_d_px * 0.12, 1),
        'kinematics_feasible': fine_fps >= 24,
    }
```

### 12.1 [R-1/P0] G-2 与全文立论基础的核心矛盾

**问题描述**：

全文的立论基础是"进球 = 加速度无突变"（1.3 节），全文 80% 篇幅围绕此构建。但 9.4 节已通过 Monte Carlo 验证证明：YOLO bbox 噪声经二阶差分放大后 SNR < 1.0，假碰撞率 97%~100%，**加速度突变检测在工程上完全不可用**。

10.2 节提出的替代方案（抛物线拟合残差 + 速度方向变化检测）仅占一小节篇幅，**缺乏同等严格的数值验证**。

**具体矛盾点**：

1. "抛物线拟合残差"需要至少 5 帧连续追踪，但 4.6 节的前提是球在篮筐区域**经常被遮挡**（消失 2~7 帧），两者矛盾
2. "速度方向变化检测"只能检测弹回型碰撞（文档自己承认），无法区分"擦筐进球"和"打板弹出后飞向别处"
3. 10.2 节的备选方案比较表是定性描述，无定量验证

**分析与验证**：

**（a）抛物线拟合残差方案的可行性分析**

核心思路：对连续 N 帧的球位置拟合二次曲线 `y = at² + bt + c`，残差大 → 有碰撞。

与二阶差分的关键区别：拟合是**多帧全局操作**（等效于低通滤波），噪声被 √N 倍抑制。

理论 SNR 分析：

```
二阶差分 SNR:  g / (√6 · σ_pos / dt²)
拟合残差 SNR:  碰撞残差 / (σ_pos / √N)

当 N=7, σ_pos=3px, dt=1/30s, g_pixel=3.19:
  二阶差分 SNR = 3.19 / (√6 × 3 × 900) = 0.00048  ❌ 完全不可用
  
拟合残差 SNR（碰撞帧残差 vs 噪声基线）:
  无碰撞: 残差 ≈ σ_pos = 3px
  碰撞帧: 残差 = 球偏离抛物线的距离
    打铁弹出: 速度反转, 1帧内位移偏差 ≈ 2×|vy|×dt ≈ 2×(4m/s)×(1/30) × 293 px/m ≈ 78px
    擦筐微扰: 速度偏移 ~20%, 偏差 ≈ 0.2×|vy|×dt × 293 ≈ 7.8px
  
  打铁 SNR = 78 / (3/√7) ≈ 68.8  ✅ 可检测
  擦筐 SNR = 7.8 / (3/√7) ≈ 6.9   ✅ 可检测（但余量不大）
```

> ✅ **结论：抛物线拟合残差在理论 SNR 上可行**，与二阶差分有本质区别。二阶差分计算的是逐帧加速度的绝对值（对噪声极度敏感），而拟合残差计算的是轨迹偏离模型的程度（多帧平均抑制噪声）。

**但前提条件约束**：需要**碰撞前**至少 5 帧的连续追踪来建立基线抛物线。碰撞发生在球接近篮筐的瞬间，此时球通常仍在空中飞行（未被遮挡），因此碰撞前的 5 帧追踪是**合理可期的**。

消失-重现分析（4.6 节）处理的是碰撞后/穿筐后球被遮挡的场景。两者处理的是**不同阶段**：

```
[阶段 A: 飞行中, 可追踪]  →  [碰撞点]  →  [阶段 B: 穿筐中, 可能被遮挡]
       ↑                        ↑                    ↑
  抛物线拟合基线（≥5帧）    拟合残差突变检测      消失-重现模式分析
```

> ✅ **两者不矛盾，处理的是进球事件的不同阶段。但文档原文表述容易让人误解为同一阶段。**

**（b）速度方向变化检测的覆盖范围分析**

| 场景 | vy 符号变化 | 可检测？ | 备注 |
|------|-----------|---------|------|
| 空心球 | 始终 vy > 0（向下） | ✅ 无符号翻转 = 无碰撞 | — |
| 擦筐进球 | vy 可能短暂减小但不变号 | ⚠️ 不翻转，需结合拟合残差 | 残差 SNR ≈ 6.9 可补充 |
| 打铁弹出 | vy 从正变负（向上弹回） | ✅ 符号翻转 = 弹回 | — |

| 打板进球 | 碰板后 vy 翻转，再翻转回来 | ⚠️ 需多段分析 | 见 R-4 |

> ⚠️ **速度方向变化检测对"侧向弹出"覆盖不足**。建议扩展为检测速度矢量方向变化（含 vx），而非仅检测 vy 符号。

### 12.3 [R-3/P1] 追踪碎片化对运动学分析的影响

**问题描述**：

4.3~4.5 节的运动学算法假设有连续的球追踪序列 `[(x₁,y₁,t₁), ...]`，但实际场景中球被遮挡是常态（手臂、篮筐、篮板、球员身体），追踪序列大概率碎片化。

**分析与验证**：

**（a）遮挡场景分类与发生概率估计**

| 遮挡类型 | 发生阶段 | 典型持续时间 | 对运动学的影响 |
|---------|---------|-------------|-------------|
| 出手遮挡（手臂挡球） | 投篮出手瞬间 | 2~5 帧 (67~167ms) | 仅影响起飞阶段，不影响篮筐附近分析 |
| 飞行中球员遮挡 | 中途 | 1~3 帧 (33~100ms) | 短暂丢失，Kalman 预测可桥接 |
| 篮筐/篮板遮挡 | 到达篮筐时 | 2~10 帧 (67~333ms) | **关键阶段**，正是碰撞检测需要的区间 |
| 篮网遮挡 | 穿筐过程 | 3~18 帧 (100~600ms) | 穿筐过程不可见，由消失-重现分析处理 |

**（b）运动学分析各算法的最低连续追踪需求**

| 算法 | 需要阶段 | 最低连续帧数 | 是否受遮挡影响 |
|------|---------|------------|-------------|
| 抛物线拟合基线 | 飞行中（碰撞前） | ≥ 5 帧 | ⚠️ 球员遮挡可能中断 |
| 拟合残差碰撞检测 | 接近篮筐时 | 基线 + 碰撞后 ≥ 2 帧 | ⚠️ 篮筐遮挡可能中断 |
| 速度方向变化 | 碰撞前后 | ≥ 3 帧（前1+碰撞+后1） | ⚠️ 同上 |
| 消失-重现分析 | 消失前 + 重现后 | 各 ≥ 1 帧 | ✅ 专为遮挡设计 |
| 反证法（无弹回） | 碰撞后观察 | 不需要连续追踪 | ✅ 检测弹回信号即可 |

**（c）碎片化容忍方案**

实际上，算法不需要"从出手到落地"的全程连续追踪，只需要在**关键阶段**有足够帧数：

```
投篮全过程:
[出手] ----飞行(0.5~1.5s)---- [接近篮筐] --[碰撞]-- [穿筐] ----[落下]
  ↑                              ↑              ↑          ↑
  不需要                      需要 ≥5 帧     需要 ≥2帧   消失-重现
                              建立基线       检测偏离     处理遮挡
```

在 30fps 下，球从出手到到达篮筐的飞行时间约 0.5~1.5s = 15~45 帧。即使中间有 2~3 次各 2 帧的遮挡中断，仍然有足够的连续片段：

```
典型追踪序列（30fps, 飞行 1.0s = 30帧）:
[■■■■■■■■ __ ■■■■■■■ __ ■■■■■■■■■■■■]
  8帧可用  丢2  7帧可用 丢2   12帧可用
                               ↑
                          接近篮筐阶段
                          足够做抛物线拟合
```

**结论与建议**：

> ✅ **追踪碎片化不构成根本阻塞**，但需要在算法中增加以下设计：
>
> 1. **分段拟合**：对每个连续追踪片段独立拟合抛物线，不要求全程连续
> 2. **最低帧数门控**：片段长度 < 5 帧时跳过运动学分析，退化到消失-重现 + 反证法
> 3. **Kalman 预测桥接**：对 ≤ 3 帧的短缺口用 Kalman 预测填充（已在 T-1.9.16 计划中）
> 4. 文档应明确声明：运动学分析（4.3~4.5 节）的适用前提是"碰撞前有 ≥ 5 帧连续追踪"

**R-3 状态**：✅ **分析完成 — 不构成根本阻塞，需增加分段拟合和最低帧数门控**

### 12.4 [R-4/P1] 打板进球处理缺失

**问题描述**：

1.3 节表格提到"打板进球"，但 4.5 节 `judge_goal_by_continuity()` 仅分析"最后一次碰撞"。打板进球的碰撞序列为：碰篮板（方向反转）→ 球改变方向 → 可能再碰筐 → 穿筐。第一次碰撞后球方向反转会被误判为"弹回 = 不进球"。

**分析与验证**：

**（a）打板进球的运动学序列**

```
时间轴:
t0: 球飞向篮板 (vy>0 向下, vx 指向篮板)
t1: 碰篮板 → 碰撞事件 ❶ (vx 反转, vy 可能反转/减小)
t2: 球从篮板反弹向篮筐 (vy 方向不定, 取决于碰板角度)
t3: 球到达篮筐上方 (vy>0 向下)
t4: 穿过篮筐 (可能有碰撞事件 ❷ = 擦筐, 也可能空心)
```

**（b）当前算法的处理路径**

```python
# 4.5 节代码中的逻辑
hoop_collisions = [c for c in collisions if c.in_hoop_region]
last_collision = hoop_collisions[-1]
if last_collision.direction_reversed:  # vy 从正变负
    return GoalJudgment(is_goal=False, ...)  # ← 打板碰撞会触发这里
```

关键点：碰撞事件 ❶（碰篮板）是否会被归入 `hoop_collisions`？

- 如果篮板在 `hoop_region`（扩展区域）内 → **是**，会被归入，且 `direction_reversed=True` → **误判为不进球** ❌
- 如果篮板不在 `hoop_region` 内 → 不会被归入，仅检测到碰撞事件 ❷（如果有的话）→ **可能正确判定**

所以问题的严重程度取决于 `hoop_region` 的定义。通常篮板紧邻篮筐上方，`hoop.height * 1.5` 的容差很可能包含篮板区域。

**（c）修正方案**

不应只看"最后一次碰撞"，而应分析**碰撞序列的模式**：

```python
# 修正：碰撞序列模式匹配
def classify_collision_sequence(collisions, hoop):

    碰撞模式分类：
    
    模式 A: 无碰撞 → 空心球
    模式 B: 单碰撞 + 仍向下 → 擦筐进球
    模式 C: 单碰撞 + 方向反转 → 打铁弹出
    模式 D: 双碰撞 (篮板区 + 篮筐区) → 打板候选

      - D2: 第二次碰撞后方向反转 → 打板未进

    """
    
    board_collisions = [c for c in collisions if c.in_backboard_region]
    rim_collisions = [c for c in collisions if c.in_hoop_region and not c.in_backboard_region]
    
    if len(board_collisions) > 0 and len(rim_collisions) == 0:
        # 碰板后无碰筐 → 可能是打板空心进球，检查最终穿越
        return "bankshot_clean"
    
    if len(board_collisions) > 0 and len(rim_collisions) > 0:
        # 打板 + 碰筐 → 看碰筐后的方向
        last_rim = rim_collisions[-1]
        if last_rim.post_collision_vy > 0:
            return "bankshot_rim_in"
        else:
            return "bankshot_rim_out"
    
    # ... 其余原有逻辑
```

### 12.5 [R-5/P1] 像素坐标 ≠ 物理坐标：视角误差未量化

**问题描述**：

9.2 节的重力估算公式 `g_pixel = 9.81 × (W_px / 0.4572) / fps²` 假设篮筐平面平行于成像平面。野球场拍摄角度通常为斜侧方（30°~60°），此时篮筐呈椭圆形，`W_px` 被透视压缩，`pixel_per_meter` 被高估。

**分析与验证**：

**（a）透视压缩的定量分析**

设相机与篮筐平面的夹角为 θ（θ=0° 正侧方，θ=90° 正上方）：

```
实际篮筐在图像中的宽度:
  水平方向（短轴）: W_px_actual = W_px_frontal × cos(θ_horizontal)
  垂直方向: 不受水平视角影响

其中 θ_horizontal 是相机与篮筐朝向之间的水平夹角
```

| 水平视角偏移 | cos(θ) | 篮筐像素宽度压缩 | g_pixel 误差 | 对碰撞阈值的影响 |
|------------|--------|----------------|------------|----------------|
| 0° (正对) | 1.00 | 0% | 0% | 无 |
| 15° | 0.97 | 3% | 3% | 可忽略 |
| 30° | 0.87 | 13% | 15% | 轻微 |
| 45° | 0.71 | 29% | 41% | ⚠️ 显著 |
| 60° | 0.50 | 50% | 100% | ❌ 严重 |
| 75° | 0.26 | 74% | 285% | ❌ 不可用 |

> 当视角偏移 ≥ 45° 时，重力估算误差超过 40%。

**（b）对各算法的影响评估**

| 算法 | 使用 g_pixel 的方式 | 误差容忍度 | 影响 |
|------|-------------------|-----------|------|
| Kalman 状态转移 | g_pixel 控制预测轨迹 | ±50% | ⚠️ 预测偏离增大，但 Kalman 会自适应修正 |
| 碰撞阈值 (N × g) | 碰撞/重力比 | ±50% | ⚠️ g 被高估 → 阈值偏高 → 漏检碰撞 |
| vy 方向判定 | 不使用 g_pixel | — | ✅ 不受影响 |
| 抛物线拟合 | 拟合系数 a ≈ g/2 | ±50% | ⚠️ 残差基线偏移，但碰撞残差仍显著大于噪声 |
| 消失-重现分析 | 不使用 g_pixel | — | ✅ 不受影响 |

**（c）缓解方案**

1. **篮筐椭圆检测**：如果 YOLO 输出的篮筐 bbox 宽高比 ≠ 1，可以估算视角。篮筐物理上是圆形，bbox 宽高比 = cos(θ)。
   
   ```python
   # 从 bbox 宽高比估算视角校正系数
   aspect_ratio = hoop_bbox_w / hoop_bbox_h
   # 篮筐物理宽高比 = 1（圆形），但考虑到透视和检测噪声
   if aspect_ratio < 0.8:  # 明显被压缩
       correction = 1.0 / aspect_ratio  # 放大回正对宽度
       hoop_w_corrected = hoop_bbox_w * correction
   ```

   > ⚠️ 此方法的局限：YOLO bbox 是矩形，不精确反映篮筐椭圆形状。更准确的方法需要实例分割或关键点检测。

2. **保守策略**：不校正，但在碰撞阈值中留更大余量。将碰撞阈值从固定值改为范围检测：

   ```
   碰撞阈值 = base_threshold × (1 + uncertainty_margin)
   其中 uncertainty_margin 可基于 bbox 宽高比估算的视角不确定性
   ```

3. **多帧篮筐位置稳定性检测**：如果篮筐在多帧中位置稳定（手持抖动已被滤除），用多帧平均的 bbox 宽度，减少单帧检测噪声。

**结论**：

> ⚠️ **视角误差在 ≤ 30° 时影响可控（g_pixel 误差 ≤ 15%），但 ≥ 45° 时需要校正**。对于野球场场景，大多数拍摄角度在 0°~45° 之间（观众/三脚架通常在侧面），因此：
>
> 1. **短期**：在碰撞阈值中增加 20%~30% 的安全余量（`collision_threshold` 从 3.0 提至 3.5~4.0），吸收视角误差
> 2. **中期**：利用 bbox 宽高比粗估视角，动态校正 `hoop_w_pixels`
> 3. **长期**：引入篮筐关键点检测，精确估算视角

**R-5 状态**：✅ **分析完成 — ≤30° 影响可控，≥45° 需要校正。短期增加阈值余量即可**

### 12.6 [R-6/P1] 反证法通道假阳性场景

**问题描述**：

反证法通道（5.4 节）的逻辑是"球到达篮筐后未观察到弹回 → 间接支持进球"，但存在以下假阳性场景：
1. 球弹出后飞出画面边界
2. 球弹回但 YOLO 未检测到（追踪丢失）
3. Air Ball（球完全没碰到篮筐，从侧面飞过）

**分析与验证**：

**（a）各假阳性场景的概率与危害评估**

| 场景 | 发生概率 | 假阳性危害 | 现有防护 |
|------|---------|-----------|---------|
| 球弹出飞出画面 | 低（篮筐通常在画面中央区域） | 高（会误判为进球） | 无 |
| YOLO 漏检弹回球 | 中（低清/远景时概率较高） | 高（同上） | 无 |
| Air Ball | 中（业余球员较多） | 中（置信度上限 0.50 限制了危害） | 部分：球须到达篮筐区域 |

**（b）防护措施设计**

```python
def channel_8_no_bounce_evidence_v2(kinematics, hoop, frame_info, window_s=1.5):
    """增强版反证法通道"""
    
    approach_time = find_last_approach_time(kinematics, hoop)
    if approach_time is None:
        return None
    
    # ---- 前置条件加强 ----
    
    # 防护1: 球必须到达篮筐中心附近（排除 Air Ball）
    approach_point = get_point_at_time(kinematics, approach_time)
    dist_to_hoop_center = distance(approach_point.pos, hoop.center)
    if dist_to_hoop_center > hoop.width * 0.8:  # 球距篮筐中心 > 0.8倍筐宽
        return None  # Air Ball 嫌疑，不使用反证法
    
    # 防护2: 球的运动方向必须指向篮筐（排除路过的球）
    if approach_point.vy is not None and approach_point.vy < 0:
        return None  # 球向上运动，不可能进球
    
    # 防护3: 检查观察窗口的完整性（排除球飞出画面）
    post_frames = get_post_window(kinematics, approach_time, window_s)
    
    # 如果观察窗口内帧数太少，说明可能视野丢失
    expected_frames = int(window_s * frame_info.fps)
    actual_frames = len(post_frames)
    observation_coverage = actual_frames / expected_frames
    
    if observation_coverage < 0.5:
        # 观察覆盖率 < 50%，反证法不可靠
        return None  # 无法确认"未弹回"还是"没看到弹回"
    
    # 防护4: 检查是否有其他球体出现在篮筐上方/侧面（弹回的间接证据）
    # ... （使用 YOLO 全帧检测结果）
    
    # ---- 弹回证据搜索（同原版）----
    bounce_evidence = search_bounce_evidence(post_frames, hoop)
    
    if len(bounce_evidence) == 0:
        # 置信度根据观察覆盖率调整
        base_confidence = min(0.50, 0.30 + actual_frames * 0.02)
        adjusted_confidence = base_confidence * observation_coverage
        
        return {
            "timestamp": approach_time,
            "confidence": adjusted_confidence,
            "detail": f"反证法: 覆盖率 {observation_coverage:.0%}, "
                      f"{actual_frames} 帧已检查, 未观察到弹回",
            "channel": "8"
        }
    
    return None
```

**关键改进点**：

| 改进 | 防护目标 | 机制 |
|------|---------|------|
| 距离门控 | Air Ball | 球必须到达篮筐中心附近 |
| 方向门控 | 路过的球 | 球必须向篮筐方向运动 |
| 观察覆盖率 | 球飞出画面 | 窗口内实际帧数/期望帧数，低于 50% 则放弃反证 |
| 置信度缩放 | YOLO 漏检 | 覆盖率越低，置信度越低 |

**R-6 状态**：✅ **分析完成 — 需增加 4 项前置防护条件，并根据观察覆盖率缩放置信度**

### 12.7 [R-7/P1] 碰撞阈值 3.0x 在有噪声条件下的有效性

**问题描述**：

9.3 节验证碰撞阈值 3.0x 可区分空心球（1.0x）和打铁（14.87x），但使用的是无噪声模拟数据。9.4 节已证明加入 YOLO 噪声后假碰撞率 100%。那么 3.0x 这个阈值是否对工程实现毫无参考价值？

**分析与验证**：

需要区分两个问题：

1. **"二阶差分加速度的绝对值"的阈值** → 这是 9.3 节验证的，9.4 节已证明不可用
2. **"抛物线拟合残差 / 噪声基线"的阈值** → 这是 R-1 中分析的替代方案，需要新的阈值

两者的阈值含义完全不同：

| 检测方法 | 阈值含义 | 9.3 节的 3.0x 是否适用 |
|---------|---------|---------------------|
| 二阶差分加速度 | `max_acceleration / g_pixel > 3.0` | ❌ 不可用（噪声 >> 信号） |
| 抛物线拟合残差 | `max_residual / σ_residual_baseline > N` | ❌ 需要新的阈值 |
| 速度方向翻转 | `vy_after × vy_before < 0` | N/A（布尔判断，无阈值） |

**抛物线拟合残差的阈值推导**：

```
无碰撞时: 残差 ~ N(0, σ_pos²)，σ_pos ≈ 3px (典型 YOLO 噪声)
碰撞时:   残差 = σ_pos + 碰撞位移偏差

阈值选择: 需要使 P(假碰撞) < 5%
  无碰撞残差服从 χ² 分布（拟合残差的平方和）
  单帧残差 > 3σ 的概率 = 0.27%
  连续 2 帧残差 > 2σ 的概率 ≈ 0.05 × 0.05 = 0.25%
  
建议阈值: 单帧残差 > 3σ_pos，或连续 2 帧残差 > 2σ_pos
  对于 σ_pos = 3px: 单帧阈值 = 9px，双帧阈值 = 6px
  
打铁弹出: 碰撞帧残差 ≈ 78px >> 9px  ✅ 可检测
擦筐微扰: 碰撞帧残差 ≈ 7.8px < 9px  ⚠️ 单帧可能漏检
  但连续 2 帧残差 ≈ 7.8px > 6px     ✅ 双帧可检测
```

**结论**：

> ✅ **9.3 节的 3.0x 阈值是"加速度/重力比"的阈值，仅对理论分析有参考价值，不能直接用于工程实现。** 工程实现应使用"拟合残差/位置噪声比"作为新的碰撞指标，建议阈值为 `单帧残差 > 3σ_pos 或连续 2 帧 > 2σ_pos`。
>
> 9.3 节的价值在于证明了"碰撞确实会产生远大于自由飞行的运动偏离"这个物理前提，替代方案只是换了一种对噪声更鲁棒的度量方式。

**R-7 状态**：✅ **分析完成 — 3.0x 阈值仅限理论参考，工程应使用拟合残差阈值（3σ / 2σ 双帧）**

### 12.8 [R-8/P2] 扣篮场景的特殊性

**问题描述**：

扣篮与投篮的运动学特征完全不同：球被人手推入篮筐（非自由飞行）、手臂严重遮挡、篮筐剧烈震动。

**分析与验证**：

**（a）扣篮的运动学特征差异**

| 特征 | 投篮 | 扣篮 |
|------|------|------|
| 球运动类型 | 自由飞行（抛物线） | 被手控制（非自由飞行） |
| 球在篮筐附近可见帧数 | 5~15 帧 | 1~3 帧（手臂遮挡） |
| 篮筐反应 | 篮网鼓包 | 篮筐整体剧烈震动 + 篮网大幅形变 |
| 加速度特征 | 碰撞前 ≈ g | 全程受手臂外力，加速度无规律 |
| 抛物线拟合 | 有效 | **无效**（非自由飞行） |

**（b）对各检测通道的影响**

| 通道 | 对扣篮的适用性 | 原因 |
|------|--------------|------|
| 运动学分析（本文核心） | ❌ 完全不适用 | 非自由飞行，抛物线假设失效 |
| 篮网形变（通道4） | ✅ 高度适用 | 扣篮篮网形变极其剧烈，最容易检测 |
| 消失-重现 | ⚠️ 部分适用 | 球被手臂遮挡而非被篮筐遮挡 |
| 反证法 | ⚠️ 部分适用 | 扣篮必然有碰撞，但球不弹回 |
| 音频 | ✅ 适用 | 扣篮音效非常显著 |
| 球员动作 | ✅ 适用 | 扣篮姿态非常独特 |

**结论**：

> ✅ **扣篮场景无需运动学分析，应由篮网形变（通道4）+ 音频（通道5）+ 球员动作（通道7）主导判定。** 在算法流程中应增加"扣篮快速识别"前置分支：
>
> ```
> if 球员手臂在篮筐高度附近 and 篮筐剧烈震动:
>     → 走扣篮判定路径（跳过运动学分析）
>     → 主要依据：篮网大幅形变 + 篮筐震动 + 音频
> ```
>
> 这不是运动学算法的缺陷，而是**适用范围的边界**。文档应在 4.1 节或 4.5 节开头显式声明"本节运动学分析仅适用于投篮（自由飞行）场景，扣篮场景由其他通道处理"。

**R-8 状态**：✅ **分析完成 — 运动学分析不适用于扣篮，需声明适用范围并增加扣篮快速识别分支**

### 12.9 [R-9/P2] 贝叶斯融合细节缺失

**（a）先验概率估算**

```
一场业余篮球赛（40分钟, 每队每场约 30~50 个进球）:

粗扫后候选区间内:
  候选区间数: ~200 个（大部分是投篮未进）

  候选区间先验 P(goal|candidate) ≈ 80/200 = 40%
```

> 融合判定发生在粗扫之后的候选区间内，先验 ≈ **40%**，这是一个信息量不大的先验，不会严重偏倚结果。

**（b）通道独立性分析**

| 通道对 | 独立性 | 原因 |
|--------|--------|------|
| 篮网形变 vs 球轨迹 | ⚠️ **不独立** | 同一物理事件（球穿网）的两个观测 |
| 篮网形变 vs 音频 | ⚠️ **弱相关** | 穿网同时产生两种信号，但噪声独立 |

| 音频 vs 球员反应 | ✅ **近似独立** | 不同信号源 |
| 反证法 vs 球轨迹 | ⚠️ **不独立** | 反证法使用球的追踪数据 |

**（c）融合方案建议**

鉴于通道间存在相关性，**朴素贝叶斯会过度自信**。建议使用以下方案之一：

| 方案 | 复杂度 | 对独立性的要求 | 适合度 |
|------|--------|-------------|--------|
| 朴素贝叶斯 | 低 | 假设独立（偏乐观） | ⚠️ 可能过度自信 |
| 加权投票 | 低 | 无 | ✅ 简单有效 |
| 分组独立贝叶斯 | 中 | 组间独立 | ✅ 推荐 |
| Dempster-Shafer | 高 | 弱于贝叶斯 | ⚠️ 过度复杂 |

**推荐：分组独立贝叶斯**

```
组1（物理信号）: max(篮网形变, 球轨迹, 反证法) → 物理置信度
组2（间接信号）: max(音频, 球员反应) → 间接置信度
最终置信度 = Bayes(物理置信度, 间接置信度)  ← 两组间近似独立
```

**R-9 状态**：✅ **分析完成 — 建议使用"分组独立贝叶斯"替代朴素贝叶斯，避免过度自信**

| 半场 3v3/5v5 | 低（~5%） | 偶尔有其他球滚入 |
| 热身/自由练习 | 高（~30%） | 多人同时投篮 |
| 个人练习 | 中（~10%） | 地上可能有多个球 |

**（b）对当前算法的影响**

当前 `IOUTracker`（及未来 `KalmanTracker`）会为每个检测到的球建立独立轨迹。问题在于：

1. **哪条轨迹对应当前投篮？** → 关联问题
2. **地上静止的球会不会干扰？** → 静止球的 vy ≈ 0，不会触发碰撞检测，影响小
3. **两人同时投篮？** → 每条轨迹独立判定，可能同时触发两个进球事件 → **可以接受**（两个球确实各自进球了）

**（c）结论**

> ✅ **多球场景不是阻塞问题**。当前的追踪器已经为每个球建立独立轨迹，每条轨迹独立做运动学分析。主要风险是：
>
> 1. 地上静止球被误追踪 → 通过"速度 > 最低阈值"过滤
> 2. 两条轨迹在篮筐附近交叉 → IoU 追踪器可能混淆 ID → Kalman 追踪器（T-1.9.16）可缓解
>
> 建议在追踪器中增加"静止球过滤"：连续 N 帧速度 < 阈值的轨迹标记为静止，排除出运动学分析。

**R-10 状态**：✅ **分析完成 — 不构成阻塞，追踪器增加静止球过滤即可**

### 12.11 [R-11/P2] 篮筐定位鲁棒性

**问题描述**：

全文运动学分析依赖 `hoop` 对象（篮筐位置），但未讨论篮筐检测失败、手持拍摄抖动导致的帧间位置跳变。

**分析与验证**：

**（a）篮筐定位的特殊性**

与球追踪不同，篮筐有两个关键特性：

1. **物理位置固定**：比赛中篮筐不会移动（除非被扣篮拉歪，很快恢复）
2. **外观稳定**：篮筐的颜色（橙色）和形状在整场比赛中不变

因此篮筐定位可以用**全局策略**而非逐帧检测：

```
方案1: 前 N 帧多数投票确定篮筐位置，之后锁定
方案2: 每帧检测，但用中位数滤波平滑位置（消除单帧跳变）
方案3: 用户手动标注（第一次使用时）
```

**（b）帧间抖动的影响**

手持拍摄的抖动幅度通常 5~20 像素。篮筐典型像素宽度 50~300px。

```
抖动 / 篮筐宽度 = 20 / 134 ≈ 15% (中景 1080p)
```

15% 的位置抖动对以下算法的影响：

| 算法 | 影响 | 原因 |
|------|------|------|
| `hoop_region` 判定 | 低 | region 通常有 1.5x 容差 |
| 穿越平面检测 | 低 | 穿越判定有容差带 |
| 反证法弹回检测 | 低 | 相对位置判定 |

**（c）篮筐检测失败的处理**

如果某帧 YOLO 未检测到篮筐：

- **粗扫阶段**：使用历史位置（篮筐不动）
- **精扫阶段**：使用粗扫阶段确定的篮筐位置

> ✅ **篮筐定位不构成严重问题**，因为篮筐物理位置固定。建议在粗扫阶段用多帧中位数确定篮筐位置并锁定，精扫阶段直接使用。

**R-11 状态**：✅ **分析完成 — 不构成严重问题，粗扫阶段锁定篮筐位置即可**

### 12.13 [R-13/P3] 连续快速进球的去重策略

**问题描述**：5.2 节提到"事件合并 + 冷静期过滤"但未给出取值依据。快攻反击可在 4~5 秒内连续进球。

```

  A 队进球 → 对方发球 → 长传 → B 队快攻上篮

  进球到球落地: ~1s
  捡球/发球: ~1s（底线发球）
  长传飞行: ~1s
  接球上篮: ~1.5s

  A 队进球 → 对方底线发球 → 运球推进 → 进攻 → 再进球

```

**（b）冷静期建议**

```

  同一篮筐冷静期 = 3.0s

经 N-4 修正后的当前建议:

#### 12.17.1 [N-1/P1] 碰撞检测角色重新定位

**问题**：2.5 节将碰撞检测的角色定位为"碰撞检测"——隐含能区分所有碰撞类型（打铁/擦筐/打板）。但验证发现：

- 打铁 SNR ≈ 51~69：可检测 ✅
- 擦筐 SNR ≈ 3~7：边界条件，检测可靠性不足 ⚠️
- 碰撞持续时间 10~20ms，30fps 下仅 0.3~0.6 帧，单帧/双帧阈值均可能漏检

**解决方案**：将碰撞检测的角色从"碰撞分类"缩窄为"**排除打铁**"。

- 打铁：残差远超阈值 → 可靠排除
- 擦筐：残差在噪声边界 → 不依赖碰撞检测通道，交由消失-重现模式 + 速度方向变化兜底
- 打板进球：多段碰撞序列 → 交由 R-4 方案（分段拟合 + 方向跟踪）

> ✅ **已在 2.5 节更新角色列为"排除打铁"，并增加 v1.5 注释说明。**

#### 12.17.2 [N-2/P1] 手持拍摄下篮筐非固定

**问题**：文档多处假设"篮筐在画面中物理固定，因此像素坐标也固定"。这仅对三脚架/固定摄像头成立。**手持拍摄是野球场最常见的拍摄方式**，篮筐像素坐标帧间抖动可达数十像素。

**解决方案**：自动检测固定/移动拍摄模式。

```
判别方法：
  取连续 N 帧（如 30 帧）的篮筐检测框中心坐标
  σ_hoop = std(hoop_center_positions)
  
  if σ_hoop < 3px:  → 固定模式：篮筐坐标取全局中位数
  else:             → 移动模式：篮筐坐标取当前帧检测值
```

**关键洞察**：YOLO 每帧已在检测篮筐（类别 `hoop`），因此逐帧篮筐坐标的获取**零额外推理成本**。仅需从固定值查表改为逐帧读取当前帧的 YOLO 检测结果。

> ✅ **已在 2.7 节适用范围中增加手持拍摄声明。**

#### 12.17.3 [N-3/P1] 反证法覆盖率逻辑矛盾

**问题**：反证法通道的前提是"球不可追踪时的兜底"，但 5.4 节的覆盖率计算 `actual_frames / expected_frames` 依赖于追踪到的帧数据——如果球可追踪，就不需要反证法；如果球不可追踪，`actual_frames` 就为零。

**解决方案**：重新定义覆盖率为两个独立指标：

1. **视口覆盖率**：事件窗口内有多少帧在视频时间线范围内（排除视频开头/结尾截断）
2. **检测覆盖率**：窗口内有多少帧有任何 YOLO 检测结果（不限于球——检测到人、篮筐等也算），证明该帧不是黑屏/模糊帧

```
combined_coverage = viewport_coverage × detection_coverage
if combined_coverage < 0.5: 放弃反证法
if combined_coverage >= 0.8: base_confidence = 0.45
else: base_confidence = 0.30
```

> ✅ **已在 5.4 节更新置信度公式和覆盖率定义。**

#### 12.17.4 [N-4/P1] 补篮场景与冷静期冲突

**解决方案**：

| 方案 | 描述 | 优缺点 |

| A. 缩短冷静期 | 降至 1.0~1.5s | 简单，但超短间隔（<1s）的误触发增加 |

#### 12.17.5 [N-5/P2] 透视投影对像素坐标的影响

- ❌ 不适用：鱼眼镜头/超广角（>120°FOV）

#### 12.17.6 [N-6/P2] 贝叶斯融合通道非独立性

  组 D（上下文组）：通道 7（因果推理链）

组间应用贝叶斯融合（各组近似独立）

#### 12.17.7 [N-7/P2] σ_pos 动态估计缺失

**问题**：全文 SNR 分析中 σ_pos = 3px 是估计值，但实际 YOLO bbox 噪声受分辨率、目标大小、运动模糊等因素影响，不同场景差异较大。

**解决方案**：从 YOLO 检测结果动态估计 σ_pos。

```
方法：取球在"近似匀速直线运动"阶段的连续 N 帧位置，
      对 x(t) 和 y(t) 分别做线性拟合，
      残差的标准差即为 σ_pos 的估计值。

触发条件：每次精扫开始时，取球的前 10~15 帧数据
回退策略：如果无法估计（球追踪不连续），使用默认值 σ_pos = 3px
```

> ✅ **方案设计完成。默认值 3px 在 720p~1080p 分辨率下合理（R-1 已验证），动态估计作为增强。**

#### 12.17.8 [N-8/P3] 弹回接球场景假阳性

**问题**：球打铁弹出后被投篮者或队友接住（未落地），此时球的速度方向变化可能类似"弹回后落下"的模式，导致反证法通道的弹回信号被球员身体遮挡。

**分析**：此场景的概率较低（需要球弹出后恰好被接住且遮挡弹回轨迹），且：
1. 打铁碰撞检测（N-1）会在此之前触发，拟合残差显著异常
2. 球被接住后消失（被球员身体遮挡），不会触发"重现在篮筐下方"的条件
3. 因果推理链通道会检查后续球员行为（无庆祝动作 → 降低进球置信度）

> ✅ **已有多通道防护覆盖。P3 级别，不构成阻塞。**

---

#### 12.17.9 [N-9/P3] 反证法置信度公式过松

**问题**：原始公式 `0.30 + actual_frames × 0.02` 在 10 帧（0.33s@30fps）即达到上限 0.50，几乎没有区分度——无论观察了 10 帧还是 45 帧，置信度都是 0.50。

**解决方案**：改为覆盖率分层计算（见 N-3 解决方案）：

```
覆盖率 >= 80% → 0.45
50% <= 覆盖率 < 80% → 0.30
覆盖率 < 50% → 放弃反证法（返回 None）
```

优势：
1. 置信度上限从 0.50 降为 0.45，保留更大的融合空间
2. 分层设计比连续公式更具工程鲁棒性（避免微小变化导致阈值翻转）
3. 覆盖率 <50% 时直接放弃，而非给出低但非零的置信度

> ✅ **已在 5.4 节代码中更新。**

## 十三、总结

### 13.1 三个核心洞察

1. **进球是时序因果事件**：不要试图在单帧中判断"球是否在篮筐内"，而要分析"球的运动轨迹是否符合进球的完整因果链"

2. **进球 = 轨迹无不连续偏离**：进球的本质是"球在篮筐区域内，运动轨迹没有发生不连续的偏离"；打铁 = 碰撞 = 轨迹突变偏离抛物线（工程上通过抛物线拟合残差检测，而非二阶差分加速度，见 R-1 / G-2）

3. **反证优于正证**：在信息不完整时，证明"球没有被弹回来"比证明"球进了"更容易做到

### 13.2 理论验证总结

| 命题 | 验证结果 | 关键数据 | 对算法实施的影响 |
|------|---------|---------|----------------|
| P1: 穿越时间 | ✅ 通过（范围修正） | 56~376ms | 文档取值从 0.1~0.3s 扩展为 0.05~0.4s |
| P2: 重力估算 | ✅ 量纲正确 | 公式成立于近似单目尺度条件 | KalmanTracker 需替换为动态计算（G-1） |
| P3: 碰撞偏离量级 | ✅ 理论对照完成 | 打铁远高于自由飞行基线 | 工程阈值改用残差 σ 阈值，不再使用 3.0x |
| P4: 噪声影响 | ✅ 通过（发现严重问题） | SNR < 1.0 | 二阶差分不可单独使用（G-2） |
| P5: 消失-重现 | ✅ 通过 | 83~583ms | 时间窗口从 [0.2, 0.8]s 修正为 [0.06, 1.0]s |

### 13.3 算法哲学

> **最好的计算机视觉方案，最终应该是在"理解故事"，而不是在"检测像素"。**

全帧连续性分析将进球检测从"空间像素匹配"提升为"时序物理推理"，这是 GoalCut 相对于现有竞品的核心算法差异化。

> ⚠️ **理论验证揭示的关键约束**：YOLO 检测噪声使得"直接计算加速度突变"这条路径在工程上完全不可用（SNR < 0.001）。碰撞检测的工程实现已明确为"**抛物线拟合残差**"（打铁 SNR 51~69），角色定位为"排除打铁"而非全碰撞分类。擦筐检测（SNR 3~7）属边界条件，由消失-重现模式 + 速度方向变化通道兜底覆盖。

## 十四、算法可行性验证缺口与下一步实验计划

### 14.1 当前结论的边界

本章只讨论**算法可行性**，不讨论工程部署、成本或上线流程。

基于前文两轮评审与修正，当前文档已经达到：

- **理论可行**：进球建模为时序因果事件的方向成立
- **方案可实现**：三道防线与降级策略在文档层面已基本闭合
- **原型可开发**：伪代码、参数区间、边界条件足以支持 PoC 编码

但当前仍**未充分证明**以下更强命题：

1. 真实视频中关键观测量（球轨迹、篮筐位置、消失-重现模式）是否稳定可观测
2. 抛物线拟合残差在真实检测噪声下，是否能稳定地区分打铁与非打铁
3. 三道防线在视角、帧率、清晰度变化下，是否仍能保持足够区分度
4. 多通道证据在冲突场景下，是否能够稳定输出“进球 / 不进球 / 证据不足”

因此，当前状态更准确地说是：

> **“理论可行 + 原型可开发”，但尚未完成“真实视频上的算法可行性闭环验证”。**

### 14.2 P0：必须补齐的算法可行性验证缺口

下表列出在“只判断算法是否成立”这一目标下，当前仍缺失的 P0 验证项：

| 编号 | 验证缺口 | 核心问题 | 为什么阻塞“算法可行”结论 | 最小补齐方式 |
|------|---------|---------|--------------------------|-------------|
| **A-1** | 真实视频闭环验证 | 理论推导是否能映射到真实视频 | 没有真实视频结果，只能证明“想法说得通”，不能证明“算法成立” | 建立小规模真实视频验证集，跑完整流程 |
| **A-2** | 关键观测量可观测性 | 碰撞前 ≥5 帧连续追踪是否常见；篮筐是否足够稳定 | 若关键观测量经常拿不到，再好的判定规则也无法工作 | 统计连续追踪率、篮筐稳定性、关键帧可见率 |
| **A-3** | 拟合残差分布实测 | 空心 / 擦筐 / 打铁 / 打板的残差分布是否分离 | 当前 `3σ / 2σ` 仍主要来自理论推导，缺真实数据支撑 | 对标注样本提取残差直方图与分布重叠率 |
| **A-4** | 粗扫候选召回率 | 真正进球是否能被候选窗口捕获 | 若粗扫漏召回，后续精扫再强也无意义 | 统计进球事件候选召回率与平均候选数 |
| **A-5** | 冲突证据与“证据不足”验证 | 轨迹、消失-重现、反证法结论冲突时能否稳定决策 | 多通道系统若无冲突样例验证，整体判定边界不可信 | 建立冲突样例集，验证融合输出稳定性 |
| **A-6** | 帧率/清晰度/视角可行性边界 | 24fps、15fps、手持、低清场景是否真的按预期退化 | 当前主要是数量级分析，缺真实视频验证 | 分场景跑对比实验，确认边界与降级策略 |

仅报告最终准确率不够。为了判断算法到底哪里成立、哪里失效，首轮实验至少要产出以下统计：

### 14.6 建议通过线（第一轮）

下表不是论文标准，只是**工程上判断“算法方向是否值得继续投入”**的建议通过线：

| 项目 | 建议通过线 | 含义 |
|------|-----------|------|
| 候选窗口召回率 | **≥ 95%** | 粗扫不能成为主要瓶颈 |
| 30fps 固定机位下关键区连续追踪率 | **≥ 60%** | 防线 1 至少在主场景中能经常工作 |

### 14.7 推荐的下一步实验顺序

为避免同时改太多变量，建议按以下顺序推进：

1. **先验证粗扫召回率**：确认真正进球没有在上游被漏掉

#### 14.9.7 推荐使用方式

- **每轮实验都新建一份记录**，不要在同一页反复覆盖
- **主结论必须可回溯到样本 ID 和配置版本**
- **若本轮没有失败样例归因表，则本轮实验默认信息不完整**
- **若本轮同时改动超过 2 个核心变量，则结果默认不可用于阈值定型**

> **一句话原则**：
>
> **实验记录模板的作用，不是让文档更漂亮，而是让“算法为什么有效 / 为什么无效”能被下一轮实验继续利用。**
