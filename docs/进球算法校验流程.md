## 一、概述

GoalCut 进球检测算法采用**多通道并行检测 + 跨通道互证融合**架构。为确保算法准确率持续达标，项目建立了一套**三层校验体系**：

```
层级 1: Ground Truth 标注 + 通道级评估（精确量化各通道 P/R/F1）
层级 2: VLM 独立扫描验证（技术正交的交叉校验）
层级 3: 端到端集成测试（全链路回归）
```

三层校验互相独立、互为补充，确保算法修改不会引入回归问题。

## 二、检测算法核心架构

### 2.1 多通道检测体系

| 通道 ID | 名称 | 最高置信度 | 依赖 | 说明 |
|---------|------|-----------|------|------|
| **1a** | YOLO 球体检测 + IOU 追踪 + 几何判定 | 0.95 | YOLO 模型 | 主判定通道，精度最高 |
| **1b** | 启发式检测（球消失/快速下落） | 0.75 | YOLO 模型 | 通道 1a 的补充 |
| **2** | 人体运动模式检测（上篮/扣篮动作） | 0.75 | YOLO 模型 | 检测球员投篮动作特征 |
| **3** | 局部运动突变检测（帧差分） | **0.35** | 无 | T-1.9.14: 从0.50降权，仅作候选触发信号 |
| **4** | 篮网有向光流穿越检测（算法C） | **0.70** | OpenCV | T-1.9.13: 替代旧版平均幅度，方向纯净度过滤 |
| **5** | 音频事件检测（入网声 + 哨声 + 击掌声） | 0.70 | WAV 音频 | 辅助信号 |
| **6** | ROI 多帧分类器 | 0.90 | 训练模型 | T-1.9.19: 以篮筐ROI为中心，多帧堆叠CNN二分类（⬜ 待训练） |
| **7** | 庆祝动作 / VLM 确认 | 0.80 | YOLO + VLM | v2.6: 检测进球后球员庆祝行为；VLM 语义确认候选事件 |

### 2.2 跨通道互证融合

各通道独立产出候选事件后，经过**跨通道互证**提升置信度：

```
各通道独立检测 → 候选事件汇总 → 跨通道互证(±2s窗口) → 事件合并(3s窗口) → 冷静期过滤(2s) → 置信度阈值过滤(0.55)
```

**跨通道互证规则**（v2.6 更新）：

- 在 ±2s 时间窗口内，检查是否存在来自**不同类型通道**的候选事件
- **仅当有 ≥1 个不同类型通道互证时**，才对事件进行置信度提升（boost）
- 单通道事件**不做 boost**，保持原始置信度
- Boost 公式：`boost = min(0.15, 不同通道数 × 0.08)`，置信度上限 0.95

**设计原因**：防止弱信号通道（如通道3，最高置信度仅0.50）在没有其他通道验证的情况下被误提升至超过阈值，导致误检。

### 2.3 关键阈值参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `confidence_threshold` | 0.55 | 最终事件过滤阈值 |
| `yolo_confidence` | 0.25 | YOLO 检测框最低置信度 |
| `validation_window` | 2.0s | 跨通道验证的时间窗口 |
| `merge_window` | 3.0s | 事件合并窗口 |
| `cooldown` | 2.0s | 确认进球后的冷静期 |
| `sample_fps` | 3.0 | 采样帧率 |

## 三、层级 1：Ground Truth 标注 + 通道级评估

> 目标：精确量化每个通道的 Precision / Recall / F1，为参数调优提供数据依据。

### 3.1 标注视频

使用交互式标注工具创建 Ground Truth：

```bash
cd goalcut

# 标注视频（自动生成 test/ground_truth/<视频名>.json）
python test/scripts/annotate.py test/input/goalcut_demo_1.MP4

# 指定输出
python test/scripts/annotate.py test/input/goalcut_demo_1.MP4 \
    -o test/ground_truth/goalcut_demo_1.json
```

**GT JSON 格式**：

```json
{
  "video": "goalcut_demo_1.MP4",
  "duration": 33.24,
  "total_goals": 4,
  "goals": [
    {"timestamp": 11.0, "note": "进球1"},
    {"timestamp": 17.0, "note": "进球2"},
    {"timestamp": 22.0, "note": "进球3"},
    {"timestamp": 27.0, "note": "进球4"}
  ]
}
```

### 3.2 运行通道级评估

```bash
# 全通道评估
python test/scripts/eval.py \
    --video test/input/goalcut_demo_1.MP4 \
    --gt test/ground_truth/goalcut_demo_1.json

# 指定通道评估
python test/scripts/eval.py \
    --video test/input/goalcut_demo_1.MP4 \
    --gt test/ground_truth/goalcut_demo_1.json \
```

## 四、层级 2：VLM 独立扫描验证

> 目标：使用视觉语言大模型（VLM）作为技术正交的独立验证器，与算法结果交叉比对。

### 4.1 技术正交性

| 维度 | 原进球检测算法 | VLM 验证器 |
|------|--------------|-----------|
| 视觉理解 | YOLO 检测框 + IOU 追踪 + 几何规则 | 端到端语义理解 |
| 决策方式 | 多通道手工规则 + 阈值融合 | 大模型 zero-shot 推理 |
| 音频利用 | STFT 频谱能量分析 | 不使用音频（纯视觉） |
| 失败模式 | 检测框丢失、遮挡、阈值敏感 | 语义误解、幻觉 |

两者失败模式完全不同，可有效交叉验证。

### 4.2 VLM 全视频扫描

VLM 独立扫描整段视频，通过滑动窗口（6s窗口、2~3s步长）找出所有进球时间点：

```bash
# 使用 run_vlm_report.py 生成标注报告
VLM_API_KEY=sk-xxx python3 test/vlm_report/run_vlm_report.py \
    --video test/input/goalcut_demo_1.MP4

# 直接调用验证脚本（含算法结果比对）
VLM_API_KEY=sk-xxx python3 test/vlm_verify/verify_vlm.py \
    --scan test/input/goalcut_demo_1.MP4 \
    --detection test/output/goalcut_demo_1_detection.json \
    --output test/vlm_verify/reports/vlm_scan_report.json
```

### 4.3 VLM 报告格式

报告输出到 `test/vlm_report/` 目录，文件名包含模型和参数信息：

```
goalcut_demo_1__dashscope_qwen-vl-max__w6s3.json
│                │          │           │
│                │          │           └─ 窗口6s步长3s
│                │          └─ 模型名
│                └─ Provider
└─ 视频名
```

报告核心字段：

```json
{
  "vlm_goals": [...],       // VLM 发现的所有进球
  "comparison": {
    "metrics": {"tp": 4, "fp": 1, "fn": 0, "precision": 0.8, "recall": 1.0, "f1": 0.889},
    "matched_pairs": [...],   // 算法与 VLM 都检测到（TP）
    "false_positives": [...], // 仅算法检测到（FP，误检）
    "false_negatives": []     // 仅 VLM 检测到（FN，漏检）
  }
}
```

### 4.4 VLM 闭环反馈

```bash
# 生成闭环反馈报告（含参数调整建议）
python3 test/vlm_verify/vlm_feedback.py \
    --report test/vlm_verify/reports/vlm_scan_report.json \
    --config configs/config.yaml \
    --output test/vlm_verify/reports/feedback.json
```

feedback.json 会给出 `PASS` / `NEEDS_TUNING` / `NEEDS_INVESTIGATION` 等状态判定，以及具体的参数修改建议。

## 六、完整校验工作流

### 6.1 日常开发校验（修改算法后必做）

```
1. 修改 ai-engine/detect.py
          ↓
2. 单独运行 AI 检测验证
   python3 ai-engine/detect.py \
       --frames-dir <帧目录> \
       --output /tmp/test_detection.json \
       --sample-fps 3 --confidence-threshold 0.55 \
       --yolo-confidence 0.25 --video-duration <时长>
          ↓
3. 对比 detection.json 与 Ground Truth
   - 检查事件数量是否与 GT 一致
   - 检查时间戳偏差（允许 ±3s）
   - 检查是否有新增误检或漏检
          ↓
4. 通过 → 提交代码
   未通过 → 分析原因 → 回到步骤 1
```

### 6.2 版本发布校验（完整三层）

```
步骤 1: Ground Truth 评估
   python test/scripts/eval.py --batch test/ground_truth/ --video-dir test/input/
   → 确认各通道指标达标
          ↓
步骤 2: VLM 独立扫描
   python3 test/vlm_report/run_vlm_report.py --all
   → 确认 VLM 与算法一致率 ≥ 80%，无新增 FP/FN
          ↓
步骤 3: 端到端集成测试
   bash test/test.sh
   → 确认全链路通过，集锦视频正确生成
          ↓
步骤 4: 回归确认
   对比新旧 detection.json
   → 确认不退化：已修复的问题未复现，指标不下降
```

### 6.3 误检/漏检排查流程

当发现算法误检或漏检时，按以下流程排查：

```
1. 查看 detection.json 中的问题事件
   - 确认 timestamp、confidence、detail（来源通道）
          ↓
2. 定位问题通道
   - detail 字段前缀标识来源：
     "几何判定" → 通道1a
     "辅助判定" → 通道1a(zone_disappear)
     "启发式"   → 通道1b
     "人体运动" → 通道2
     "运动突变" → 通道3
     "篮网形变" → 通道4（旧版平均幅度）
     "篮网有向穿越" → 通道4（v2.5 有向光流算法C）
     "入网声"   → 通道5
     "哨声"     → 通道5
          ↓
3. 单通道复现
   python channel_test.py --frames-dir <帧> --channels <通道ID> --video-duration <时长>
          ↓
4. 分析根因
   - 误检(FP)：阈值过低？通道特异性不足？跨通道误 boost？
   - 漏检(FN)：阈值过高？信号太弱？篮筐检测偏移？
          ↓
5. 修复验证
   - 调整参数或修改逻辑
   - 重新运行评估确认修复
   - 回归测试确认不影响其他视频
```

## 七点五、算法配置 Profile 系统（v2.6 新增）

引擎 v2.6 引入了 **算法配置 Profile 系统**，支持通过 `--algorithm-profile` 参数选择预定义的通道组合方案，无需手工调参即可切换检测策略：

### 7.5.1 预定义方案

| 方案名 | 说明 | 启用通道 | VLM |
|--------|------|---------|-----|
| `default` | v2.5 全通道 | 1a,1b,2,3,4,5 | 禁用 |
| `pickup_with_net` | 半场野球场（篮网清晰） | 1a,1b,3,4,5 | 常态过滤 |
| `pickup_no_net` | 半场野球场（篮网不清/无网） | 1a,1b,3,5 | 常态过滤 |
| `minimal` | 仅核心视觉，最低误报 | 1a,1b | 禁用 |
| `vlm_primary` | VLM 主导，低阈值粗筛 | 1a,1b,3,5 | 常态过滤（全范围） |
| `vlm_only` | 纯 VLM 扫描，禁用所有视觉/音频 | 无 | 滑动窗口全视频扫描 |

### 7.5.2 vlm_only 模式

`vlm_only` 是 v2.6 新增的纯 VLM 模式，**完全不使用任何视觉或音频检测通道**，而是由 VLM（通义千问 qwen-vl-max）以滑动窗口方式扫描全视频：

- 窗口参数：6s 窗口、2s 步长（`scan_step` 已从 3.0 调整为 2.0）、每窗口 8 帧
- 用途：作为独立基准验证，或在 YOLO 通道完全失效的场景下提供备选
- 限制：受 VLM 随机性影响，同一窗口不同次调用可能判断不同；成本较高（按 API 调用计费）

```bash
# vlm_only 模式运行示例
go run cmd/goalcut/main.go -input video.mp4 -algorithm vlm_only
```

### 7.5.3 使用算法配置进行校验

不同 Profile 的检测结果可交叉对比，用于评估各通道组合的实际效果：

```bash
# 对同一视频跑多种 Profile，对比输出
for profile in default pickup_no_net vlm_primary vlm_only minimal; do
    go run cmd/goalcut/main.go \
        -input test/野球场素材/IMG_7225_1.mp4 \
        -output test/output/${profile}/ \
        -algorithm $profile
done

# 比对各 Profile 的检测事件数和置信度分布
```

## 八、案例：5.67s 误检修复（2026-03-08）

### 问题

`goalcut_demo_1.MP4` 检测到 5 个进球，但 Ground Truth 和 VLM 扫描均确认只有 4 个。5.67s 处的事件为误检：

```json
{
  "timestamp": 5.67,
  "confidence": 0.691,
  "detail": "运动突变(left_hoop): score=60.3, 阈值=34.7, 后续衰减=0.7"
}
```

### 根因分析

1. **来源**：通道3（局部运动突变），原始置信度 0.55
2. **问题**：跨通道验证时，±2s 窗口内碰巧有其他通道的候选事件，被 boost 到 0.691 超过阈值
3. **本质**：单个弱信号通道（通道3最高仅0.55）通过 boost 机制"搭便车"产生误报

### 修复方案

**跨通道互证改进**（`ai-engine/detect.py`）：

1. 将跨通道验证改为**仅在有不同类型通道互证时才 boost**，单通道事件保持原始置信度不变
2. 将通道3的置信度上限从 0.55 降为 0.50，确保单通道3事件（无互证）低于 0.55 阈值被过滤

### 验证结果

| | 修改前 | 修改后 |
|---|--------|--------|
| 检出事件数 | 5（含 1 个误检） | 4（与 GT 完全一致） |
| 5.67s 事件 | conf=0.691 ✗ | 已过滤（无互证，conf≤0.50） |
| 10.33s | conf=0.83 | conf=0.90（多通道互证 boost ↑） |
| 15.67s | conf=0.65 | conf=0.65（单通道，无变化） |
| 21.0s | conf=0.882 | conf=0.732（单通道，无误 boost） |
| 26.67s | conf=0.75 | conf=0.90（多通道互证 boost ↑） |
| Precision | 80% (4/5) | **100%** (4/4) |
| Recall | 100% (4/4) | **100%** (4/4) |
