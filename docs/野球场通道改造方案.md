## 二、改造策略：逐通道独立验证 → 数据驱动组合

### 2.1 核心原则

```
不预设权重 → 每个通道独立改造 → 用视频跑出单通道 P/R/F1
→ 根据实测数据选出最佳通道组合 → 自动搜索最优权重
```

**为什么不直接拍脑袋定权重**：
- 当前项目已证明预设权重（视觉 0.70 + 篮网 0.20 + 音频 0.10）在真实野球场 F1 仅 11%
- 每个通道的实际信噪比因视频条件差异巨大
- 只有在多个视频上实测后，才知道哪些通道真正有效

### 2.2 改造分为三个阶段

```
阶段 A：基础修复（止血） ──── 预计 8h
    修好现有通道的信号质量，不加新通道

阶段 B：新通道开发 ────────── 预计 40h
    开发新的检测通道，每个独立可测

阶段 C：数据驱动组合 ────────── 预计 8h
    用测试视频自动搜索最佳通道组合与权重
```

## 三、阶段 A：基础修复（止血）

### A-1：通道 2 降权改造

**问题**：通道 2 检测"上篮动作"，投篮命中率只有 40~50%，天然 50%+ 误报。

**改造方案**：

```python
# 修改 ai-engine/detect.py
# 方案一（短期止血）：直接降权
WEAK_CHANNEL_CAPS["人体运动"] = 0.35  # 从 0.55 降至 0.35

# 方案二（中期改造）：改为仅在有强通道佐证时才保留
# 通道 2 事件必须在 ±2s 内有通道 1a 或 VLM 佐证，否则丢弃
```

**涉及文件**：`ai-engine/detect.py`
**预计工时**：1h
**验证方式**：对 amateur_game_04 跑评估，确认误报数从 28 大幅下降

### A-2：跨通道互证分层

**问题**：弱通道（2/3）互相佐证制造"虚假共识"。

**改造方案**：

```python
# 通道可信度分级
CHANNEL_TIERS = {
    "tier_1_strong": ["几何判定", "辅助判定", "VLM确认"],     # 强信号
    "tier_2_medium": ["篹网有向穿越", "入网声", "启发式"],     # 中信号
    "tier_3_weak":   ["人体运动", "运动突变", "哨声"],         # 弱信号
}

# 互证规则改造：
# - 弱 + 弱 → 不互证
# - 弱 + 中 → 小幅 boost（0.05）
# - 任意 + 强 → 正常 boost（0.08~0.15）
```

**涉及文件**：`ai-engine/detect.py`
**预计工时**：3h
**验证方式**：对所有 GT 视频跑评估，确认高置信度误检数下降

### A-3：VLM 改为常态通道

**问题**：VLM 仅在球覆盖率 < 10% 时触发，实际很少启用。

**改造方案**：

```python
# 方案：VLM 作为后置过滤器，对所有置信度 0.35~0.70 的候选事件做确认
# 不改变现有检测流程，只在最终输出前增加 VLM 过滤步骤

def vlm_filter_candidates(candidates, video_path, threshold=0.35):
    """
    对置信度在 [threshold, 0.70) 的候选事件调用 VLM 确认。
    - VLM 确认进球 → 保留，置信度 boost
    - VLM 否认进球 → 降低置信度（大概率被过滤）
    - 置信度 >= 0.70 的高置信事件不经 VLM（已足够可信）
    """
```

**涉及文件**：`ai-engine/detect.py`
**预计工时**：4h（复用已有 VLM 代码）
**验证方式**：对 amateur_game_04 跑评估，Precision 应显著提升

### A-4：Ground Truth 标注

**问题**：仅 2 个视频有可靠 GT，无法量化评估。

**操作**：


每个新通道独立开发，独立验证，不影响现有通道。

### B-3：ROI 多帧分类器（O-16）

**目标**：以篮筐为中心裁剪 ROI，堆叠 8~15 帧，输入轻量 CNN，直接判断进球/未进。

**为什么对半场野球场价值最高**：
- 固定机位 + 单篮筐 → ROI 位置极稳定 → 训练数据一致性高
- 不依赖篮网（学习球运动、光照变化等多维时序特征）
- 端到端学习，无需手工设计规则

**实施步骤**：

```
步骤 1: 数据收集（O-15）
    - 从已有视频中按篮筐 ROI 裁剪片段
    - 进球片段：GT 时间戳 ±1s 范围
    - 未进片段：随机采样非进球时段（含篮下对抗、投篮未进等）
    - 目标：300+ 片段（进球/未进各半）

步骤 2: 模型训练（O-16）
    - 模型：MobileNetV3-Small
    - 输入：(128, 128, N×3)，N=12 帧
    - 输出：二分类 [进球, 未进]
    - 导出 ONNX 供推理

步骤 3: 集成为通道 6（O-17）
    - 在 detect.py 中新增通道 6
    - 输入：篮筐 ROI 坐标 + 候选时间窗口的帧序列
    - 输出：进球概率 [0, 1]
    - 置信度上限：0.90
```

**涉及文件**：新增 `ai-engine/train/`、`ai-engine/roi_classifier.py`、修改 `ai-engine/detect.py`
**预计工时**：36h（数据收集 8h + 训练 20h + 集成 8h）

**单通道验证**：

```bash

# 关注指标：
# - 单通道 Precision ≥ 85%（最关键——ROI 分类器的价值在于低误报）
# - 单通道 Recall ≥ 70%
```

### 5.2 通道筛选规则

根据单通道基准数据，按以下规则筛选：

```
入选条件（至少满足一项）：
├── 规则 1: 单通道 F1 ≥ 40%（独立有效的通道）
├── 规则 2: 单通道 Precision ≥ 70%（误报极低，可作为确认信号）
└── 规则 3: 单通道 Recall ≥ 80%（漏检极少，可作为触发信号）

淘汰条件（满足任一则排除）：
├── 规则 4: 单通道 Precision < 20%（纯噪声）
└── 规则 5: 在 ≥2 个视频上 TP = 0（完全无效）
```

### 5.3 自动权重搜索

对筛选出的通道组合，自动搜索最优权重：

```python
# test/scripts/optimize_weights.py（新增）

import itertools
import numpy as np

def grid_search_weights(channel_results, gt_events, channels):
    """
    网格搜索最优权重组合。

    输入：
    - channel_results: 各通道在各视频上的检测事件列表
    - gt_events: 各视频的 GT 事件
    - channels: 参与搜索的通道列表

    搜索空间：每个通道权重 [0.0, 0.05, 0.10, ..., 1.0]
    约束：所有权重之和 = 1.0

    评估指标：加权 F1（Precision 权重 1.5 × Recall 权重 1.0）
    野球场场景 Precision 优先，宁可漏检也不误报。
    """

    best_f1 = 0
    best_weights = None

    for weights in generate_weight_combinations(channels, step=0.05):
        fused_events = fuse_with_weights(channel_results, weights)
        p, r, f1 = evaluate(fused_events, gt_events,
                            precision_weight=1.5)
        if f1 > best_f1:
            best_f1 = f1
            best_weights = weights

    return best_weights, best_f1


def evaluate_combination(channel_subset, channel_results, gt_events):
    """
    评估特定通道子集的最优表现。
    用于回答"哪些通道该留、哪些该去"。
    """
    best_weights, best_f1 = grid_search_weights(
        channel_results, gt_events, channel_subset)
    return {
        'channels': channel_subset,
        'best_weights': best_weights,
        'best_f1': best_f1,
    }


def find_best_combination(all_channels, channel_results, gt_events):
    """
    遍历所有可能的通道子集（2^N），找出 F1 最高的组合。
    N 通常 ≤ 8，搜索空间可控。
    """
    results = []
    for r in range(2, len(all_channels) + 1):
        for subset in itertools.combinations(all_channels, r):
            result = evaluate_combination(
                list(subset), channel_results, gt_events)
            results.append(result)

    results.sort(key=lambda x: x['best_f1'], reverse=True)
    return results[:10]  # 返回 Top 10 组合
```

### 5.4 验证流程

```
步骤 1: 收集单通道数据
    对每个通道 × 每个视频，记录所有检测事件（时间戳 + 置信度）
              ↓
步骤 2: 自动搜索
    python test/scripts/optimize_weights.py \
        --channel-results test/eval_results/ \
        --ground-truth test/ground_truth/ \
        --output test/eval_results/best_combination.json
              ↓
步骤 3: 输出最佳组合
    {
      "best_combination": {
        "channels": ["1a", "6", "vlm", "5"],
        "weights": {"1a": 0.35, "6": 0.30, "vlm": 0.20, "5": 0.15},
        "metrics": {
          "precision": 0.85,
          "recall": 0.78,
          "f1": 0.81
        }
      },
      "runner_up": { ... },
      "per_video_breakdown": { ... }
    }
              ↓
步骤 4: 人工确认
    - 检查最佳组合在每个视频上的表现是否均衡
    - 确认没有某个视频 F1 特别低（过拟合风险）
```

## 六、场景自适应：篮网可见性检测

不同视频篮网清晰度不同，系统应自动检测并切换策略：

```python
# ai-engine/detect.py 新增

def detect_net_visibility(frame_files, hoop_cx, hoop_cy, hoop_w):
    """
    分析前 30 帧，判断篮网是否可见。

    方法：
    1. 裁剪篮筐下方 ROI（篮网理论位置）
    2. 计算 ROI 内的边缘密度（篮网有密集的网格纹理）
    3. 计算 ROI 内的颜色均匀性（无网时较均匀，有网时纹理丰富）

    返回：'clear'（篮网清晰）/ 'unclear'（篮网不清/无网）
    """
    edge_density = compute_edge_density(roi_frames)
    texture_variance = compute_texture_variance(roi_frames)

    if edge_density > THRESHOLD_EDGE and texture_variance > THRESHOLD_TEX:
        return 'clear'
    return 'unclear'
```

**根据篮网可见性动态调整策略**：

| 通道 | 篮网清晰 | 篮网不清 |
|------|---------|---------|
| 1a（球轨迹穿越） | 正常权重 | **权重提升**（成为绝对主力） |
| 4（篮网光流） | 正常权重 | **禁用**（信号不存在） |
| 5 入网声 | 正常权重 | **禁用或大幅降权** |
| 6（ROI 分类器） | 正常权重 | **权重提升**（不依赖篮网） |
| VLM | 正常权重 | **权重提升**（语义理解不受影响） |
| 5 叫好/击掌声 | 正常权重 | **权重提升**（替代入网声的音频信号） |

### 10.1 预定义方案

引擎 v2.6 支持通过 `--algorithm-profile` 选择预定义的算法组合方案：

| 方案名 | 说明 | 启用通道 | VLM |
|--------|------|---------|-----|
| `default` | v2.5 全通道 | 1a,1b,2,3,4,5 | 禁用 |
| `pickup_with_net` | 半场野球场（篮网清晰） | 1a,1b,3,4,5 | 常态过滤 |
| `pickup_no_net` | 半场野球场（篮网不清/无网） | 1a,1b,3,5 | 常态过滤 |
| `minimal` | 仅核心视觉，最低误报 | 1a,1b | 禁用 |
| `vlm_primary` | VLM 主导，低阈值粗筛 | 1a,1b,3,5 | 常态过滤（全范围） |
| `vlm_only` | **纯VLM扫描**（v2.6 新增） | 无 | 滑动窗口全视频扫描（6s窗口、2s步长） |

### 10.3 自定义算法配置文件

创建独立 YAML 文件，通过 `--algorithm-config` 加载：

```yaml
# my_custom_profile.yaml
description: "我的自定义配置"
channels:
  1a:
    enabled: true
    confidence_cap: 0.95
  1b:
    enabled: true
    confidence_cap: 0.70
  2:
    enabled: false
  3:
    enabled: false
  4:
    enabled: false
  5:
    enabled: true
    confidence_cap: 0.60
cross_validation:
  window: 2.0
  boost_per_channel: 0.08
  max_boost: 0.15
vlm:
  enabled: true
  mode: "always"
  confirm_range: [0.30, 0.65]
detection_overrides:
  confidence_threshold: 0.40
```

```bash
python3 ai-engine/detect.py \
    --frames-dir /tmp/frames \
    --output /tmp/result.json \
    --algorithm-config my_custom_profile.yaml \
    --source-video video.mp4 --vlm-confirm
```

### 10.4 配置优先级

```
--algorithm-config（独立文件） > --algorithm-profile（预定义方案）
    > --channel（通道过滤） > 代码默认值（全通道）
```

### 10.5 核心配置项说明

| 配置项 | 类型 | 说明 |
|--------|------|------|
| `channels.<id>.enabled` | bool | 通道开关 |
| `channels.<id>.confidence_cap` | float | 该通道置信度上限（即使被互证也不超过此值） |
| `cross_validation.window` | float | 跨通道互证时间窗口（秒） |
| `cross_validation.boost_per_channel` | float | 每多一个互证通道的 boost 增量 |
| `cross_validation.max_boost` | float | 互证 boost 上限 |
| `vlm.enabled` | bool | 是否启用 VLM |
| `vlm.mode` | string | `fallback`=仅1a失效时, `always`=常态过滤 |
| `vlm.confirm_range` | [float,float] | VLM 确认的置信度范围 [min, max) |
| `detection_overrides.*` | 各类型 | 覆盖全局检测参数（阈值、帧率等） |
